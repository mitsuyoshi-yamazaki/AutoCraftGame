# Issue 002: INSTRUCTIONS_PER_TICKが大きすぎる

## 症状

Mini-Cコンパイラが生成するコードは1つの関数呼び出しに30-50命令を使い、
if-elseチェーン（7段）だけで数百命令を消費する。
replicatorプログラムの1tick分の処理には数千〜数万命令が必要。

現在のデフォルト値: 100,000命令/tick。

## 影響

- シミュレーション速度の低下（1tickあたりの計算量が大きい）
- パフォーマンス上のボトルネック（特にキャラクター数が増えた場合）

## 原因

Mini-Cコンパイラのコード生成効率:
- 全ての比較でPUSH/POP/LIのオーバーヘッド
- ゲームAPI呼び出し（sense, move等）がそれぞれ10-20命令に展開
- 関数呼び出しのプロローグ/エピローグ

## 改善方針

1. **コンパイラの最適化**: レジスタ割り当ての改善、不要なPUSH/POPの削除、定数畳み込み
2. **命令セットの拡張**: 複合命令（比較＋分岐を1命令で行う等）の検討
3. **プログラムの簡略化**: 深いif-elseチェーンを避ける設計
4. **段階的対応**: まず動作を優先し、パフォーマンスは後で改善
