# GUI描画対象オブジェクト一覧 — v3

ゲームシステム上、連続座標（Position）を持ち、GUIの連続空間上に描画しうるオブジェクト種別を列挙する。

v2からの主要な変更: 全オブジェクトがグリッド上のセルではなく、連続座標上の円として描画される。各オブジェクトは衝突半径を持ち、描画サイズはこの半径に基づく。

---

## 1. ResourceNode（資源ノード）

マップ上に配置された採取可能な資源源。キャラクターが一定距離内（INTERACT_RANGE）からHARVESTアクションで原料を取得する対象。有限資源であり、枯渇すると消滅する。

- **id** — 一意な識別子
- **type** — ノード種別
  - `OreNode`（鉱石ノード）: Oreを産出
  - `CrystalNode`（結晶ノード）: Crystalを産出
- **remaining** — 残存資源量（整数）
- **position** — 連続座標 `{x, y}`（浮動小数点数）

### 描画要件

- 油田や鉱脈のような、資源を獲得/採掘できるオブジェクトのメタファー
- 衝突半径（RESOURCE_NODE_RADIUS）に基づくサイズの円で描画する
- remaining量に応じて濃淡が変化すべき（多い＝濃い、少ない＝薄い）
- 資源の種類が、色で明確に表現されるべき

v2からの変更:
- 描画サイズがCHARACTER_RADIUSベースのスケールに変更。形状はv2の角丸矩形を踏襲する

### LOD（簡略描画）

画面上サイズが閾値以下の場合、単色の円に簡略化（OreNode=金茶色、CrystalNode=水色、remaining比率で透明度変化）。

## 2. EnergyNode（エネルギーノード）

マップ上に配置されたエネルギー供給源。毎tickエネルギーを生産し、上限まで蓄積する。キャラクターが一定距離内からRECHARGEアクションで回収する。

- **id** — 一意な識別子
- **productionRate** — tickあたりのエネルギー生産量
- **stored** — 現在の蓄積量
- **maxStored** — 蓄積量の上限
- **position** — 連続座標 `{x, y}`（浮動小数点数）

### 描画要件

- エネルギー源（太陽、泉、発電所など）のメタファー
- 衝突半径（ENERGY_NODE_RADIUS）に基づくサイズの円で描画する
- stored量に応じて濃淡が変化すべき（多い＝明るい、少ない＝暗い）
- ResourceNodeともCharacterとも視覚的に区別できるべき

v2からの変更:
- 描画サイズがENERGY_NODE_RADIUSベースのスケールに変更。形状はv2のダイヤモンド形を踏襲する

### LOD（簡略描画）

画面上サイズが閾値以下の場合、単色の円に簡略化（金色、stored比率で透明度変化）。

## 3. Remains（残骸）

キャラクターが死亡した際にその位置に残されるオブジェクト。コンポーネントとインベントリを保持し、他のキャラクターがDISASSEMBLEで回収できる。

- **id** — 一意な識別子
- **components** — 死亡キャラクターのコンポーネント一覧
- **inventory** — 死亡キャラクターのインベントリ
- **position** — 連続座標 `{x, y}`（浮動小数点数）

### 描画要件

- 死骸や残骸のメタファー
- 衝突半径（REMAINS_RADIUS）に基づくサイズの円で描画する
- キャラクターに似た形状だが、明らかに「死んでいる」ことが伝わる見た目
- 内容物の多寡がおおまかにわかることが望ましい（完全に空になったら消滅する）

（v2と同一の描画要件。形状のみ円に変更）

### LOD（簡略描画）

画面上サイズが閾値以下の場合、単色の円に簡略化（灰色）。

## 4. Character（アクティブキャラクター）

`program` が非nullの活性キャラクター。毎tick、Programに従って自律行動する。

- **id** — 一意な識別子（例: `char-001`）
- **position** — 連続座標 `{x, y}`（浮動小数点数）
- **velocity** — 速度ベクトル `{vx, vy}`（浮動小数点数）（v3で追加）
- **durability** — 現在の耐久値（毎tick -1、0以下で死亡）
- **energy** — 現在のエネルギー量
- **components** — 搭載コンポーネント一覧（Body構成）
  - Frame, Actuator, Sensor, Processor, Harvester, Assembler, Disassembler, Charger, MemoryCore の任意組み合わせ
- **inventory** — 所持アイテム（アイテム名 → 個数）
- **mass** — 質量（コンポーネント+インベントリの原料換算合計）（v3で追加、描画は直接行わないが情報パネルで表示）
- **最大耐久値** — Frame数 × FRAME_DURABILITY（componentsから導出）
- **現在のAction** — そのtickで実行中のアクション

### 描画要件

- 単細胞生物のメタファーであり、内部コンポーネントは細胞内小器官のメタファーである
  - 生物であるため、曲線で構成される見た目になるべき
- 衝突半径（CHARACTER_RADIUS）に基づくサイズの円で描画する
- 格納されているコンポーネントの種類と数が大体見た目から判断できる状態が理想
- 現在の耐久値が大体見た目から判断できる状態が理想
- インベントリがどの程度埋まっているかが確認できることが望ましい
- エネルギー残量が視覚的に把握できることが望ましい

v2からの変更:
- 描画サイズがCHARACTER_RADIUSベースのスケールに変更。形状・内部構造（コンポーネントリング等）はv2を踏襲する
- 速度・加速度ベクトルの描画は行わない

### LOD（簡略描画）

画面上サイズが閾値以下の場合、黒円の中にdurability比率に応じたサイズの赤円を描画。赤円のサイズがdurability残量により変化する。コンポーネントリング等の詳細は省略。

## 5. InactiveCharacter（非アクティブキャラクター）

`program` がnullの非活性キャラクター。ASSEMBLEで生成された直後の状態で、WRITE + ACTIVATEされるまで行動しない。

- **id** — 一意な識別子
- **position** — 連続座標 `{x, y}`（浮動小数点数）
- **velocity** — `{vx: 0, vy: 0}`（生成直後は静止）
- **durability** — 初期耐久値（Frame数 × FRAME_DURABILITY）
- **energy** — 親から移転されたエネルギー（基礎代謝で減少し続ける）
- **components** — 搭載コンポーネント一覧（親のASSEMBLE指示で決定）
- **inventory** — 空（生成直後は常に空）

> アクティブ / 非アクティブの区別は `program` フィールドのnull判定による。型としては同一の `Character` だが、描画上は明確に区別する（色・形状等）。

### 描画要件

- Characterと同様だが、アクティブなCharacterとは明確に区別のつく見た目
  - グレースケール表示や、半透明な黒系統の色を重ねる、など

（v2と同一）

## 6. 壁（ワールド境界）（v3で新規追加）

ワールドの矩形境界。不動オブジェクトであり、キャラクターが衝突すると反発力が発生する。

### 描画要件

- ワールドの矩形領域の外周を線で描画する
- 色は暗い灰色（`#333333`）で、背景から区別できる程度
- 派手である必要はない（環境の枠組みとして控えめに表示）

## 補足: 位置を持たない概念（描画対象外）

以下はゲームシステム上の重要な概念だが、それ自体はマップ座標を持たないため、連続空間上への直接描画の対象ではない。サイドパネルやオーバーレイ等での情報表示に用いる。

- **Inventory内アイテム** — Ore, Crystal, Metal, Circuit, Frame, Actuator 等。キャラクターの所持品として表示
- **Program** — キャラクターの行動ルール群。選択キャラクターの詳細パネルで表示
- **SimulationEvent** — character_spawned / character_died。イベントログとして時系列表示
- **World統計** — 現在tick、生存キャラクター数、累計誕生・死亡数、ResourceNode残存数、EnergyNode総stored。統計パネルで表示
- **質量** — キャラクターの構成とインベントリから導出。選択キャラクターの詳細パネルで表示
- **速度** — キャラクターの速度ベクトル。選択キャラクターの詳細パネルで表示
