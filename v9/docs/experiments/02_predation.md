# 実験02: 捕食（R5）

## 目的

捕食性個体が成立し、それに利得があることを実証する（3_v9_goal「捕食性個体の存在」）。
システムは「分解可能」という物理法則のみを提供し、**何を攻撃するかはプログラムが判断する**
（R6・R7: システムは捕食者/被捕食者を区別しない）。

## セットアップ

- 獲物: 実験01の祖先種コロニー（(50,50)、クレードルで増殖する）
- 捕食者: Processor + Storage + Disassembler + Sensor + Actuator の5コンポーネント種
  （(58,50)、SCAN射程10でコロニーに届く距離）。複製はしない
- 捕食者プログラム: [src/programs/predator.ts](../../src/programs/predator.ts)
  - 休眠（コロニーが育つのを待つ、tick 1500まで）→ SCAN(filter=Processor)で最寄りの獲物を探す
    → Sensorの返す方向へActuatorで推進 → 射程内(距離≤2)で停止しDISASSEMBLE →
    分解産物を回収 → 次の獲物へ
- 実行: `npm run sim -- --predation --ticks 3000 --seed 42`

## 結果（seed=42, 3000tick）

| 指標 | 値 |
|------|-----|
| 捕食（DISASSEMBLE除去）回数 | 複数回（テストで2件以上を保証） |
| 獲物の種別 | すべて Processor |
| コロニー稼働Processor | 捕食開始時7 → 終了時1 |
| 捕食者Storageの回収物 | EncodedFragment×N, InfoSeed×N ほか（RX1=Processor分解の出力） |
| 原子保存 | 完全維持（捕食を通じても不変） |

- 捕食者は休眠から目覚め、Sensorで探知した方向へ移動し、コロニーのProcessorを次々に分解した
- **捕食の利得が構造的に成立している**: Processorの分解（RX1）は希少な情報系素材
  （EncodedFragment・PatternChain・InfoSeed）を返す。これは自然界のI原子ノード（rare）を
  掘るより高効率な入手経路であり、「捕食を選択肢に入れる利点」（3_v9_goal）が実データで確認された

## 考察

1. **R5（捕食性個体）を実証**: 事前定義の種族ではなく、**プログラムの判断としての捕食**が成立した。
   同じシミュレータ・同じ物理法則の上で、複製する種（実験01）と捕食する種（本実験）が
   別々のプログラムとして共存する
2. **捕食は個体群動態を大きく変える**: 単一の捕食者が7個体まで育ったコロニーを1個体まで削った。
   これは生態系のダイナミクスを高める淘汰圧である（v2のScavengerと異なり、能動的な移動と
   探知を伴う真の捕食）
3. **闘争/逃走の選択圧が潜在する**: 捕食者はActuatorで能動移動する。獲物側がActuatorを獲得すれば
   逃走が可能になり、移動コスト（エネルギー・摩耗）を伴う軍拡が始まる素地がある
4. **システムは中立**: シミュレータには「捕食」という概念はない。あるのはDISASSEMBLE（分解）と
   SCAN（探知）とTHRUST（推進）だけで、それを「他個体を狩る」目的に組み合わせたのはプログラムである
