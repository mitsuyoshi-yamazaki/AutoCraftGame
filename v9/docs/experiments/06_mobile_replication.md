# 実験06: 移動複製種（局所枯渇からの脱出）

## 目的

実験05は「定住種は局所資源を枯らすと移動できず必ず絶滅する」ことを示し、移動能力の適応価値を
定量化した。本実験では**移動しながら自己複製する種**を実装し、資源を探索採取して繁殖し、
子もまた移動種であるために系統が局所枯渇から脱出して空間へ広がることを実証する。

事前の判断（コア変更の要否）: 移動が必要とする能力（推進 THRUST、方向付き SCAN、
移動中の HARVEST、複製、pmem複写）はすべてv9のコアに既存で、実測で6部品グループが世界を
横断移動できることを確認した。よって**シミュレーションの根幹は変更せず、v9で実装した**。
唯一の追加は pmem サイズの拡大（下記）で、これは加算的なパラメータ変更である。

## 実装

### 探索採取プリミティブ（[helpers.ts](../../src/programs/helpers.ts) forageOne）

移動種の中核。ある物質を1個回収するために:
1. 各周回の先頭でグループエネルギーを確認し、低ければ EnergyNode を探して移動・回収する
   （枯渇するとProcessorが餓死凍結し回復不能なため、探索より優先する）
2. SCAN(filter=物質)で対象を探し、見つかれば方向へ Actuator で推進して接近、射程内で Harvester が採取
3. 見つからなければ自前LCGで方向を選んで彷徨し、再SCANする

### 移動複製種（[mobile.ts](../../src/programs/mobile.ts)）

6部品（Processor + Assembler + Storage + Harvester + Sensor + Actuator）。
サイクル: 材料を探索採取（forageOne×表）→ 27工程クラフト → 6部品の子を組立 → 持参金転送 →
自pmem複写 → 子を起動 → 分散（親が離れる）→ 先頭へ。子も同じ6部品移動種である。

### pmemサイズの拡大（1024 → 4096語）

定住型複製子（ancestor）は600語（コード＋表）で1024語pmemに収まった。しかし移動＋探索採取＋6部品の子を
持つ移動複製子はコードが約1400語に達し、1024語では収まらなかった。これは**16bitアドレス空間の
範囲内でのパラメータ拡大（1024→4096）で解決した**。既存プログラムは自分のサイズ内でしか
動作しないため影響を受けず、全既存テストが変更なしで通過することを確認した。
これはアーキテクチャの変更ではなく、より複雑な行動に必要な作業領域の拡大である。

## 結果（seed=42, 散在資源＋潤沢エネルギー環境）

- **移動複製に成功**: 個体は資源を求めて世界中を移動し（InfoSeed等の希少資源を探して数十単位
  移動）、材料を集めて6部品の子を組み立て、プログラムを複写して起動した。子も6部品の移動種
- **空間への拡散**: 個体は世界の対角（100×100の世界で最大93〜103単位＝ほぼ端から端）まで
  離れて分布した。定住種（同条件のancestor）は全個体が生誕地(50,50)の半径15単位以内に留まった
  （拡散の差は3倍以上。test/mobile.test.ts で検証）
- **原子保存・決定論**: 移動・探索・複製・分散を通じて原子総量は保存され、同一シードの2回実行は
  完全に一致する
- 4シード中3つで複製に成功（1シードは初回採取中の凍結で失敗）。移動種の成立は環境（資源密度）に
  依存する

## 実装過程で発見した知見

| 事象 | 対策 |
|------|------|
| forage/forageEnergyが全レジスタ(r3-r6)を破壊し、ループ状態が壊れて材料が2個で停止 | ループのポインタ・カウンタをメモリ（グローバル）に退避 |
| 移動探索の推進エネルギーが尽きてProcessorが餓死凍結（回復不能） | forageOneに毎周回のエネルギー確認＋ヒステリシス補給を組み込み、推進コストを下げ予備を厚くした |
| クラフト工程順でBaseSolid/VolatileCoreが一時枯渇（再生産工程が後段） | 再生産工程を消費工程の間に挟むよう並べ替え、必要な材料緩衝＝運搬質量を削減 |
| 1024語pmemに移動複製子が収まらない | pmemを4096語へ拡大（加算的変更） |

## 考察

1. **移動種が局所枯渇から脱出することを実証した**。定住種（実験05）は局所資源を枯らすと
   絶滅するしかないが、移動種は世界中に拡散して新しい資源域に到達する。実験05で定量化した
   Actuatorの適応価値が、実際に動く種として実現された
2. これで進化の勾配（定住 → 移動）の**両端が同じv9世界のプログラムとして実現**された。
   移動という戦略もまた、システムが提供するのではなくプログラムが実装するものである
3. **移動はエネルギー的に高コスト**である。推進の消費に加え、エネルギー自体も探索採取が必要で、
   数世代後にはエネルギー枯渇や壁際トラップで凍結しやすい。定住種より繁殖の持続が難しいという
   トレードオフが観察された。これは「移動は資源到達性を得る代わりにエネルギーコストを払う」という
   自然な選択圧であり、環境（資源・エネルギー密度）が移動種の成否を左右する
4. **真の空間競争の基盤**が整った。移動種は空間を動き回るため、資源やニッチを巡る空間的な
   競争・共存が初めて意味を持つ（実験05で定住種には空間競争が存在しなかったのと対照的）。
   複数の移動種による空間競争の観察は次の課題である

## この実験が「進化のプログラマビリティ」に加えたもの

同じv9世界の上で、プレイヤーは定住戦略と移動戦略を**どちらもプログラムとして**書き分けられる。
移動種の探索採取・分散・エネルギー管理はすべてプログラムの実装であり、システムは物質・力・
探知・採取・複写という物理法則しか提供しない。局所最適（定住・省エネ）と広域探索（移動・高コスト）
という生態戦略の対立が、プログラムの違いとして世界に現れる。
