# 実験08: 長命移動複製種（器官の維持が繁殖能力になる）

## 目的

実験06の移動複製種は、移動能力と資源の認識能力を持ち自己複製もできるが、**繁殖が続かない**。
本実験では、同じ能力構成のまま**繁殖能力（寿命 × 生涯の子の数）が高い個体**を作り、
その差がどこから生まれるのかを実データで示す。

## 移動複製種が早逝する理由（実測）

`--mobile` を15000tick走らせ、器官ごとの耐久度と残骸化のtickを記録した（seed=42）。

| 器官 | 摩耗の内訳 | 実測の減り方 | 残骸化 |
|------|------------|--------------|--------|
| Sensor | 経年 + **SCAN 1回ごとに1** | 約0.42/tick | **t=2710（最初）** |
| Harvester | 経年 + HARVEST 1回ごとに1 | 約0.28/tick | t=5490 |
| Processor | 経年 + 継続動作 | 約0.20/tick | t=6980 |
| Actuator | 経年 + 作動中の継続動作 | 約0.16/tick | t=5690 |
| Assembler / Storage | 経年 + 動作1回ごとに1 | 約0.10/tick | t=9520 / t=9930 |

探索採取はSCANの連打であり、Sensorだけが突出して速く削れる。耐久度1000は
**最初の採取フェーズ1回分（約2500tick）で尽きる**。Sensorを失った個体は資源も
エネルギーも探知できず、彷徨ってエネルギーを使い切り、餓死凍結する（実測: t=4000に
グループエネルギー0）。以降は複製できないまま朽ちる。

これは「移動は高コストだから続かない」（実験06の考察3）よりも具体的な死因である。
**移動複製種は寿命ではなく、感覚器の摩耗で死んでいた。**

## 実装（[longevous.ts](../../src/programs/longevous.ts)）

構成は移動複製種と完全に同じ6部品（Processor + Assembler + Storage + Harvester +
Sensor + Actuator）、推進・エネルギー管理の定数も同じ。加えたのは3点だけである。

### 1. 器官の点検と修理（`maintainGroup`。[helpers.ts](../../src/programs/helpers.ts)）

自分はSELF_DURABILITY、他のメンバーはCSCAN結果の耐久度（aux欄）で調べ、閾値600を
下回った器官をAssemblerのREPAIRで修理する。修理が材料・エネルギー不足で拒否されても
結果コードが返るため停止しない。閾値600は回復量400（`repairAmount`）を捨てない上限であり、
**修理の間隔を空けること自体が延命になる**（修理コストは回数に比例して増えるため）。

### 2. 点検の位置——探索の1周ごと（本種の成否を分けた点）

当初は工程の切れ目（採取1個ごと・クラフト1工程ごと）でのみ点検した。これでは**足りなかった**。
希少物質（InfoSeed、SignalFluid）の探索は1個の採取に数千tickかかることがあり、その間
プログラムは `forageOne` の中から出てこないので点検が一度も走らない。実測では
SignalFluidを探している最中にSensorが死に、移動複製種と同じ末路をたどった。

そこで `forageOne` に**探索の1周ごとに差し込むコード**（`perRound`）を足し、そこで点検する
ようにした。省略時は何も出力しないので、既存の種のプログラムは1語も変わらない。
コストは1周あたり1tick（CSCANのhalt）である。

### 3. 修理材料の供給——キット工程と持参金

修理材料（Sensor:PatternChain / Harvester・Actuator:ConductiveGel / Processor:EncodedFragment /
Assembler:ChargedBinder / Storage:BindingShard）は、複製工程の副産物では足りない。そこで:

- **サイクルの先頭に修理キット工程を置く**。サイクルの最後に作ったのでは、最初の採取
  フェーズの途中で死ぬので間に合わない
- 採取とクラフトを1つの工程表（`PLAN_STEPS`）として順に実行する**インタプリタ**に変えた。
  これで「採取→クラフト→採取→クラフト」と交互に書けるようになり、キットを先頭に置ける
- PatternChainはInfoSeed（rare）を要する。**最初のInfoSeedを見つける前にSensorが死ぬ**ため、
  親個体には初期在庫として、子には**持参金として修理材料を持たせる**
  （親が自分の分を作るついでに子の分まで作る）

### 4. 初期配置——独立した祖先個体を複数置く

単一祖先だと、系統の成否がその個体の籤（希少資源をいつ見つけるか）に丸ごと左右される
（実験06の「4シード中3つで成功」はこの籤である）。既定では世界(100×100)を等分する位置に
**4個体**を50単位離して置き、個体ごとに乱数種（seedSalt）を変える。乱数種を揃えると
彷徨の方向まで一致してしまい、別々に置いた意味がなくなる。
移動複製種との1対1比較には `{ founders: 1 }` を使う。

## 結果1: 移動複製種との対照（単一祖先、40000tick、移動種と同じ環境）

| | 移動複製種 | 長命移動複製種 |
|---|---|---|
| 生まれた個体数（seed=42） | 2 | **6** |
| 生まれた個体数（seed=2） | 1（複製できず） | **7** |
| 祖先個体の寿命（seed=42） | 6,980 tick | **22,820 tick（3.3倍）** |
| 祖先個体の寿命（seed=2） | 7,150 tick | **16,870 tick（2.4倍）** |
| 系統の存続（seed=42） | t=9,479で絶滅 | 40,000tick時点で存続（同時4個体） |
| 最初の器官の残骸化 | t≈2,500（Sensor） | t≈13,000〜15,000 |
| 最大修理回数 | 0 | 17 |

4シード（42/7/2/99）すべてで20000tick時点の系統が存続し、移動複製種はすべて絶滅していた。
原子保存と決定論（同一シード2回の完全一致）は維持されている。

## 結果2: 祖先4個体・20000tickのシード走査

既定の初期配置（4個体）で seed 1〜40 を20000tick走らせ、**累計誕生回数**
（一度でも稼働したProcessorの数 − 祖先4）を数えた。原子保存は全シードで維持された。
括弧内は結果3の対策を入れる前の値である。

| | 値 |
|---|---|
| 平均 | 31.6回（6.2回） |
| 中央値 | 30回（6回） |
| 最小 | 15回（0回。**繁殖に失敗するシードが無くなった**） |
| 最大 | **52回（13回）** |

最大は seed=26（誕生52・同時ピーク42）で、以下 40（48）、31（45）、21（45）と続く。
**seed=26 を実験の既定シードとした**（`EXPERIMENTS` の `longevous`、CLIの `--longevous`）。

シード間の開き（15〜52回）は依然として大きく、祖先が最初のInfoSeed（rare、世界に6ノード）を
いつ見つけるかの籤が効いている。ただし対策前のような**全滅シードは消えた**。

## 結果3: 30000tickの全滅と、その原因・対策

祖先4個体の既定配置で60000tickまで延ばすと、個体数はt=20000で15を数えたあと**t=37500で全滅**した。
誕生はt=25000（累計14）で止まり、以後は増えないまま減るだけだった。

### 原因の切り分け

候補として挙がった「死骸由来の地面堆積が移動を妨げる」は**該当しない**。
[physics.ts](../../src/sim/physics.ts) の `collectBodies` が剛体として扱うのはグループと
単独コンポーネントだけで、地面堆積・資源ノード・エネルギー塊は衝突計算に入らない。
残骸コンポーネントは剛体だが、`decayProbability`（1/2000）で崩壊するため蓄積せず、
実測でも常時10〜20体で頭打ちだった。

実際に起きていたのは**エネルギー収支の破綻**である。世界の総貯蔵エネルギーは
t=12500の22,833をピークに単調減少し、全滅時には0になっていた。支出側の内訳は:

1. **修理コストの逓増**（`repairBaseEnergy × (修理回数+1)`）。修理回数17で1回720エネルギーに達し、
   Storage容量2000の3分の1を1回の修理が食う。摩耗速度が一定である以上、修理回数は時間に比例し、
   生涯の修理費は時間の2乗で増える（実験04の壁）
2. **SCANの撃ちすぎ**。SCANは1回5エネルギーかつSensorを1摩耗させる。探索は1周2〜4tickで
   撃ち直していたが、推進は静止から始まるので2tickでは**ほとんど進まない**。
   進まないまま撃つSCANが、エネルギーとSensorの両方を削っていた
3. **修理材の捨て値**。REPAIRは新品と引き換えに摩耗材を等量その場へ排出する（原子保存）。
   これを拾わないため、修理のたびに材料1個を捨て、その分をInfoSeedから作り直していた

### 対策（3つとも「拾い方・動き方」の変更で、シミュレータは変えていない）

| 対策 | 内容 |
|---|---|
| 弾道的な移動 | 接近4tick・彷徨12tick（従来2/4）。同じ距離をより少ないSCANで進む。`forageOne` の `approachTicks`/`wanderTicks` |
| 摩耗材の回収 | REPAIR成功直後、足元に排出された摩耗材をHarvesterで拾い直す。`maintainGroup` が器官種別から修理材料表を引いてフィルタに使う |
| 経路上の拾い上げ | 探索中のSCANに写った**射程内の**有用物（EncodedFragment / PatternChain / InfoSeed / ConductiveGel / ChargedBinder）を、目的の物質でなくても回収する。追加のSCANは不要。`forageOne` の `pickupTable` |
| 在庫駆動の工程 | 採取は「在庫がN個になるまで」、クラフトは「指定物質の在庫が足りていれば丸ごと飛ばす」。回収品で賄えた分だけ採掘・合成が減る |
| 情報原子の再生 | InfoSeedが尽きたら、回収したEncodedFragmentからR20（I循環の閉路）でInfoSeedを作り直す。材料が無ければ飛ばす（失敗許容工程） |

### 結果（seed=12、既定4個体）

| | 対策前 | 対策後 |
|---|---|---|
| 同時稼働のピーク | 15（t=20,000） | **35（t=40,000）** |
| 累計誕生 | 14 | **92** |
| 系統の絶滅 | **t=37,500** | t=150,000でようやく1個体 |
| t=30,000時点 | 稼働3・貯蔵エネ3,418 | 稼働21・貯蔵エネ60,625 |
| 地面に捨てた物質（t=20,000） | 477個 | 122個 |

**30000tickの全滅は解消した。** エネルギーは減るどころか蓄積へ転じ（t=30,000で60,625）、
個体数はt=40,000で35に達する。

### 残る限界: 情報原子の総量

対策後の系統も、t=50,000でInfoSeedノード6本を**使い切った**あとは緩やかに縮小する。
情報原子(I)は世界に1,209個しかなく（rare資源6ノード×200）、終了時にはその大半が
地面に散っていた（PatternChain 497 + EncodedFragment 388 + InfoSeed 164 ＝ 1,049個）。
拾い上げは射程内に写ったものだけを1個ずつ拾うので、死骸が世界中に散るほど回収が追いつかない。
**個体数の上限を決めているのは、もはや寿命でも修理費でもなく、世界の希少原子の総量と
その回収効率である。**

## 考察

1. **繁殖能力の差は、繁殖の仕組みではなく維持の有無から生まれた。** 複製の工程も子の構成も
   移動複製種と同じで、増やしたのは「壊れる前に直す」ことだけである。それだけで祖先個体の
   寿命が2〜3倍になり、生涯の子の数がそれに比例して増えた
2. **自己修復は単独では負けるが、複製と組めば勝つ。** 実験04は、修理コストが回数の2乗で
   効くため自己修復種は再生産種に勝てないと示した。本種はその結論を覆さない——修理回数は
   17に達し、1回あたり720エネルギー（`repairBaseEnergy × (回数+1)`）とStorage容量2000に
   迫っている。ただし**修理で買った時間の中で子を作る**ので、コストの壁に当たる前に系統は
   次の世代に渡っている。維持は目的ではなく、繁殖までの時間を買う手段として機能する
3. **最も弱い器官が寿命を決める。** 摩耗はすべての器官で進むが、系統の存続を決めていたのは
   最速で減る1つ（Sensor）だけだった。この個体が長命なのは、全身を均等に直すからではなく、
   探索の1周ごとにSensorを点検するからである
4. **系統の寿命を決めるのは個体の寿命ではなく、物質循環の閉じ方だった。** 器官の維持で個体の
   寿命の壁を越えると、次は世界の側の壁（エネルギー収支、次いで希少原子の総量）が現れた。
   そして前者は「動き方と拾い方」を変えるだけで越えられた。捨てていた摩耗材を拾い、
   経路上の分解物を拾い、在庫で足りる工程を飛ばす——どれもプログラムの書き方である
5. **希少資源の探索が繁殖速度の律速である。** 祖先を4個体に増やしても誕生数は0〜13回と
   大きくばらつき、その差は最初のInfoSeedをいつ見つけるかで決まっていた。維持で寿命の
   制約を外したことで、次の制約——rare資源の探索効率——が前面に出た形である
6. **親から子への資源の受け渡しが、戦略の成立条件だった。** 修理材料は希少資源を要するため、
   生まれたばかりの個体は自力で用意する前に感覚器を失う。親が持参金として渡すことで初めて
   この戦略は世代を越える。**維持戦略は単独の個体の性質ではなく、親子2世代にまたがる性質である**

## この実験が「進化のプログラマビリティ」に加えたもの

繁殖能力という淘汰に直結する形質が、システムのパラメータではなく**プログラムの書き方**で
2〜3倍変わることを示した。同じ部品・同じ物理法則・同じ環境で、点検を入れる位置と持参金の
中身を変えただけである。移動複製種と長命移動複製種を同じ世界に置けば、後者が選択されるはずで、
それは進化がシステムではなくプログラムの側で起きることの、もっとも直接的な実例になる。
