# GUI（観察アプリ）仕様

ヘッドレスCLIに加え、実験結果をブラウザで視覚的に観察するGUIを提供する。
過去バージョン（v3/v8）のUIと同じ流儀（vite + canvas + 制御バー + 側パネル）だが、
描画は依存を増やさないため素のCanvas 2Dで実装する（v8はpixi.js）。

## 起動

```bash
npm run ui         # 開発サーバー（http://localhost:5173）
npm run build:ui   # 静的ビルド（dist/）
npm run verify:ui  # 視覚言語の機械検査（色・形・寸法、生の色の直書き）
```

観察アプリとは別に、視覚言語そのものを調整・検査するダッシュボードを
`http://localhost:5173/visual-language.html` に置く。

## 実験の選択

`src/experiments.ts` の `EXPERIMENTS` に登録された実験をドロップダウンで選ぶ。各実験は
初期状態config（seedから生成）と専用パラメータ（例: 移動種は資源密度の高い環境）を持つ。
登録済み: 祖先種の自己複製 / 変異 / 自己拡張 / 自己修復 / 捕食 / 移動複製 / 長命移動複製 /
録画用 / 空間競争。

## 録画用の字幕（実験 `recording`）

生態のサイクル（誕生・増殖・枯渇・死・崩壊・還流）を録画して外部へ見せるための仕組み。
**字幕はログの可視化ではなく解説**である。したがって種類ごとに数回だけ、一度に一つ出す。

| 役割 | 置き場所 |
|---|---|
| 世界（資源の薄い `recording`） | `src/experiments.ts` の `RECORDING_PARAMS` |
| 台本づくり（ヘッドレス） | `src/tools/recording-script.ts` → `ui/recording-captions.json` |
| 字幕の出し入れ | `ui/captions.ts`（`CaptionPlayer`） |
| 場所の印 | `ui/renderer.ts` の `setHighlight` |

設計上の決めごと:

- **シミュレータには手を入れない。** 枯渇（MatterNodeの消滅）と還流（崩壊由来の地面堆積が減る）は
  ワールドの差分で観測する。イベントを足さないので、物理も保存則も既存実験の挙動も動かない
- **台本は先に作る。** v9は決定論なので、同じ版・実験・シードなら台本のtickと実機のtickは一致する。
  崩壊のように「対象が消えること自体が出来事」であるものは、起きてから字幕を出しても目撃できない。
  先に計算しておき、**発生の数秒前から出して**そこを見ておけるようにする（見た目は発生前後で変えない）
- **印は対象と一緒に動く。** 個体は移動するので、座標に置きっぱなしでは対象を指せない。
  対象がまだ現れていなくても印は出す（予告になる）。ただし**発生が済み、対象が発生地点から
  大きく離れたら印を消す**——そこに対象は居ないので、残すと間違った場所を指すことになる。
  対象が消えた出来事（崩壊・枯渇）は、その地点が出来事の場所そのものなので印を残す。
  字幕のほうは離れても発生地点に留める（対象と一緒に画面を飛び回るほうが読めなくなるため）
- **字幕は印の真下に、一定の間隔で置く。** 画面外へはみ出しても追い込まない。
  指し示す対象が無い字幕（増殖のような世界全体の話）は印を出さず、マップ中央に置く
- **枯渇は字幕にしない。** 資源ノードは残量が減っても表示の下限に張り付くため、消える瞬間が
  画面でほとんど読めず、字幕を出しても何を見ればよいか分からない。出来事の検出自体は残して
  あるので、`--survey` で「枯渇の起きるシードか」はこれまでどおり確認できる
- **物質の固有名は字幕に出さない。** 見る側に意味が無いので一般名で言う（"material"）
- **台本が合わなければ字幕を出さない。** 実験・シード・`GAME_VERSION` を照合し、
  違えばその旨だけを出す（ずれた字幕は嘘になる）
- **秒⇄tickは実測のtick速度で換算する。** UIは1コールバック1tickで描画も挟むため、
  速度スライダの値は上限の希望でしかなく、実際は下振れする。表示時間は実時間で計る
- 台本には `gameVersion` / `experimentId` / `seed` と各行の tick・座標・文面を持たせ、
  **第三者が同じものを再生成できる**状態で残す

## 視覚言語

`ui/simulation-ui-kit/CONVENTION.md` の規約に従う。ただし**色覚多様性への対応は範囲外**とする
（プロトタイプのためアクセシビリティを考慮しない。2026-09-22 判断）。色の弁別は通常視の
色差だけで検査し、キットが出す色覚3型の警告は参考扱いにする。

**値は手で選ばない**——色は処方
（面の色・原典の系列・彩度の寄せ方）から導出し、形は生成器から導出する。
符号化の定義は `ui/visual-language-model.js` **1か所だけ**が持ち、観察アプリと
ダッシュボードが同じものを読む。以下はその定義の写しであり、コードが正である。

### 符号化表（規約 A-5。画面の側パネルにも出す）

| チャネル | 運んでいるもの |
|---|---|
| **形** | 大分類（物質・個体・単独部品・エネルギー） |
| **色相** | 種別。黄はエネルギー専用、2段の無彩色は構造系と廃棄系の専用 |
| **大きさ** | 量（**面積に比例**）。エネルギー湧出点は量を持たないので固定 |
| **位置** | 場所（ワールド座標） |
| **長さ** | 耐久（個体は外周の弧、単独部品は内側の塗りの高さ） |
| **明度** | 豊富な物質の区別（構造系＝明・廃棄系＝暗の2段） |

### 大分類（形）

| 大分類 | 形 | 面積係数 | 最小 | 備考 |
|---|---|:---:|:---:|---|
| 個体（グループ） | 円 | 1.8 | 2.2px | **主体なので最も大きく最も鮮やか。** 外周の弧が使えるのも円だけ |
| 物質（MatterNode・地面の物体） | 菱形（辺は直線・角だけ丸い） | 0.7 | **2.6px** | 資源は無機的なので辺を曲げない |
| 単独部品 | 横長 | 0.45 | 1.0px | 加工された＝プリミティブな形状から離れた形。遠景まで残る唯一の差 |
| エネルギー | 四角 | 0.2 | 1.2px | 湧出点と散布で扱いが違う（下記） |

角丸はマークの大きさに依らず一定の px（1.5px）にする。角丸は識別のための形ではなく描画の仕上げなので、
データ量に連動させない。**面積合わせは角を丸めない菱形の値で固定する**——面積はシミュレーション上の
量の表現であり、角丸は装飾なので、装飾で量の表示が動いてはいけない。

物質の最小 2.6px は、量にすると約700相当（基準4000のとき）。希少資源（初期量200）が
点に潰れて存在すら読めなくなるのを避けるための誇張で、規約 B-3 が明示的に許容している
（「小さすぎて見えない個体を実寸で描く意味はない」）。**代償として、下限に当たっている
資源は残量が減っても大きさが変わらない**——希少資源の枯渇は大きさでは読めず、
クリックして残量を見ることになる。

### 色

処方は `categorical: 'Paired'`、面は `#14201a`、彩度は**個体 0.95・環境 0.75**の2組を
同じ面から導出する。鮮やかな点が個体、くすんだ点が環境になる（規約 A-4）。

**予約色**は他のクラスへ割り当てられない。導出したカテゴリ色のうち予約色から ΔE 15 未満の
ものは、割り当ての候補から機械的に外れる。

| 予約色 | 持ち主 |
|---|---|
| 黄 | エネルギー（湧出点・散布）。**処方を変えても動かない** |
| 無彩色・明 | 構造系の物質、その他の部品 |
| 無彩色・暗 | 廃棄系の物質 |

物質のカテゴリは 構造系(S/B)・廃棄系(X)・活性系(A)・伝達系(T)・情報系(I)・触媒系(C) の6つ。
豊富な構造系と廃棄系を無彩色へ逃がすことで、色が付いているものが希少資源か生物だけになる。
個体の種は 定住種 / 移動種 / 捕食者、単独部品は Harvester / Actuator / Disassembler /
Assembler ＋その他4種（色の予算が4なので畳む）。

### 状態（規約 A-6。identity が使っていないチャネルへ載せる）

| 状態 | チャネル | 対象 |
|---|---|---|
| 平均耐久 | 外周の弧 | 個体（円のときだけ描かれる） |
| 耐久 | 内側の塗りの高さ | 単独部品 |
| 稼働中の Processor 数 | 中心の点（0〜4） | 個体 |
| 選択 | 縁の有無 | 全て |
| 当tickの残流量 | 薄い同形の下敷きに重ねた**面積** | エネルギー湧出点 |

**状態のために形・色相を変えない。回さない。**

残骸は「状態」ではなく別の表示クラスとして扱う——生存部品の無い個体も、耐久0の単独部品も、
**種ではなく不活性な物質**なので予約色の無彩色（構造系と同じ灰）で描く。
弧も塗りも空になるので、同じ灰の「その他の部品」とは区別できる。

### 資源の状態と大きさの対応

`src/sim/types.ts` が持つ状態に素直に対応させる。**同じ量を2つのチャネルへ載せない。**

| オブジェクト | 持っている状態 | 描き方 |
|---|---|---|
| MatterNode | 物質種 + 残量（減るだけ・再生せず・0で消滅） | 大きさ＝残量。内側の塗りは使わない |
| 地面の物体 | 物質種 + 個数 | 同じ形で大きさ＝個数 |
| EnergyNode | **量を持たない。** 当tickの流出量のみ | 固定サイズ。当tickの残流量ぶんの面積で黄を重ねる |
| 散布エネルギー | 量 | 大きさ＝量 |

## 描画

- **操作**: ドラッグでパン、ホイールでズーム、クリックで最寄りオブジェクトを選択
- 個体を最後に描いて前景へ置く（重なったときに主体が隠れない）
- 面の色・文字色は CSS 変数として `main.ts` がトークンから流し込む。
  **CSS にも描画にも生の色を書かない**（`npm run verify:ui` が検査する）

## 制御とメトリクス

- 制御: 実験選択・seed入力・リセット・再生/停止（Space）・1tickステップ・速度（tick/s）・フィット
- メトリクス: tick、種別の個体数、グループ数、移動種の拡散距離、誕生/死亡累計、
  コンポーネント種別数、資源ノード数、原子総量（保存確認）、蓄積エネルギー
- 選択詳細: 個体（構成部品・耐久・稼働状態）、資源ノード（残量）等

## 実装との関係

- GUIは `src/sim/` のシミュレーション本体をそのまま駆動する（`executeTick`/`buildInitialWorld`）。
  乱数はシード付きPRNGを保持し、決定論はCLIと同一（同一実験・同一seedで同じ展開）
- GUIはシミュレーション仕様を一切変更しない。観察のための表示層である
