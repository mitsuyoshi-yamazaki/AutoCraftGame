# ワールド・オブジェクト・決定論 仕様

## ワールド

- WORLD_WIDTH × WORLD_HEIGHT の連続2D空間。壁あり（トーラスではない）
- 時間はtick単位で進む

## オブジェクトモデル

世界に存在するオブジェクトは以下の種別のみ。全オブジェクトは世界で一意の数値ID
（生成順の連番）を持つ。

| 種別 | 動く | 衝突 | 説明 |
|------|:---:|:---:|------|
| コンポーネント | ○（剛体として） | ○ | 8種（[02_components.md](02_components.md)）。活性または残骸（wreck） |
| グループ | ○ | ○ | 接続されたコンポーネントの連結成分。メンバーはグループの座標を共有する |
| 地面の物体 | × | × | Storageに入っていない物質（散布されたもの）。1オブジェクト=1物質×個数 |
| MatterNode | × | × | 自然産出物質の鉱脈。有限量、再生しない |
| EnergyNode | × | × | エネルギー湧出点。無限総量・毎tick流量制限つき |

- 「キャラクター」「個体」という種別は存在しない（R7: 個体境界の非定義）。
  観察上の個体はグループという物理的帰結にすぎない
- 単独コンポーネントは要素数1の剛体として扱う（グループオブジェクトは作らない。v8と同様）

## 初期状態

初期状態は設定（config）とシードから決定論的に生成される:

1. MatterNodeの配置: 物質種別ごとに個数・初期量（abundanceに応じたパラメータ）。
   位置はPRNGで非重複に決定（種別の定義順 → 各ノードの順に消費）
2. EnergyNodeの配置: 個数分、同様にPRNGで決定
3. 祖先種の配置: configで座標・構成・プログラム・初期Storage内容を明示指定する
   （PRNGを消費しない。実験の再現性と制御のため）

補助として、configは「クレードル配置」（祖先の近傍に各種MatterNode/EnergyNodeを保証する配置）を
指定できる。移動能力を持たない最小祖先の成立に必要（[06_ancestor_scenario.md](06_ancestor_scenario.md)）。

## 決定論（R8）

- 乱数はシード付きPRNG（v3の `createRng` = mulberry32変種、定数 0x6d2b79f5）のみを使用する。
  `Math.random()` の使用は禁止
- 乱数の消費点と順序:
  1. 初期化: ノード配置（上記の順。1試行あたり x, y の2回）
  2. 毎tick: 自発変化の判定（対象オブジェクトのID昇順に1回ずつ）
- それ以外のすべての処理は決定論的（反復順序は常にオブジェクトID昇順、
  ただし物理フェーズの走査は剛体ID昇順）
- 検証基準: 同一シード・同一config・同一tick数の実行結果（全オブジェクトの状態）が
  バイト単位で一致すること

## ゲームループ（1tickのフェーズ順）

```
0. ノード帳票リセット（EnergyNodeの当tick流出量カウンタを0に）
1. Processor実行フェーズ（running かつ PROC_TICK_COST を支払えたもの、ID昇順）
   - VM命令を最大 instructionsPerTick 実行
   - I/O読み書きは即時反映（opmem書込・pmem書込は対象のpendingに蓄積し、
     フェーズ1終了時に一括反映。v8と同様）
2. コンポーネントアクションフェーズ
   2-1. DISCONNECT処理（トリガの立っている Processor → Assembler の順、各ID昇順）
   2-2. アクション処理（コンポーネントID昇順）:
        進行中の多tickアクション（SET_RECIPE/CRAFT/ASSEMBLE/DISASSEMBLE）の進行、
        新規トリガ（HARVEST/TRANSFER/SCAN/REPAIR等）の実行
3. 自発変化フェーズ（対象=残骸・地面のコンポーネント物体、ID昇順、PRNG判定）
4. 劣化フェーズ（経年・継続動作の耐久度減少。耐久度0になったものは残骸化）
5. 物理フェーズ（推進・摩擦・衝突・壁 → 積分 → 位置クランプ。剛体ID昇順）
6. tick++
```

- アクションのトリガは操作メモリへの書込で立ち、フェーズ2-2で処理される
  （v8のSCAN即時実行とは異なる。結果はプログラムからは次tickのフェーズ1で見える）
- エネルギーの消費タイミング: フェーズ1（Processor実行）、フェーズ2（アクション・レシピ）、
  フェーズ5（Actuator推進）
