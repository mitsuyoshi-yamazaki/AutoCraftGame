# v9 設計判断

[1_design_discussion.md](1_design_discussion.md) の未決事項（Q5〜Q8・未着手論点）への回答と、
[４_v9_discussion.md](４_v9_discussion.md) のアイデアの採否を確定する。
本書は判断と根拠の記録であり、実装可能な形式の仕様は [../specs/](../specs/) に置く。

## Q5: 物理モデル → (a) 力ベース物理に戻す

- v3-v5方式（力→加速度→速度→位置、摩擦、バネ反発衝突）を採用する
- Actuatorが推進力を発生する。**ランダム移動は廃止**する
- これにより `Math.random()` の使用理由が消え、シード付きPRNGによる決定論（R8）を復元する
- 根拠: バネ反発を導入する以上、力の枠組みは必要。移動にエネルギーコストを課すことで
  「逃げるコスト」（3_v9_goal の闘争/逃走の選択圧）が成立する

## Q6: 辺スロットの対称性 → (a) 対面辺の自動割当

- コンポーネントAの辺iにBが接続されるとき、B側は辺 (i+3) mod 6 が使用される
- 対面辺が使用済みの場合、その接続は失敗する
- 根拠: 決定論的で最も単純。将来六角格子に幾何的意味を与える場合にも整合する

## Q7: ASSEMBLE時の辺指定 → 明示指定＋AUTO

- ASSEMBLE操作は「接続先コンポーネント（ローカルID）」と「接続先の辺インデックス0〜5」を指定する
- 辺に AUTO（0xFF）を指定した場合は接続先の空き辺のうち最小インデックスが選ばれる
- 新規コンポーネント側の辺はQ6のルールで決まる（対面辺）

## Q8: コンポーネントの役割分担

| コンポーネント | 役割 | 補足 |
|---|---|---|
| Assembler | CRAFT（レシピ実行）、ASSEMBLE（組立・接続）、REPAIR（修理） | 材料・エネルギーは同グループのStorageから自動で引き当てる。自身のバッファは持たない |
| Processor | プログラム実行（v8互換VM） | 自身のpmem読取と、同グループの他Processor/MemoryCoreへのpmem書込が可能（v8の0x2000系を維持） |
| MemoryCore | 拡張記憶 | pmem領域をI/O経由で読み書きできる受動部品。祖先種の必須構成には含めない |
| Actuator | 推進力の発生 | 方向・強さを操作メモリで指定。作動中は毎tickエネルギー消費＋摩耗 |
| Sensor | SCAN（周囲の探知） | 種別コード・距離・方向・一時IDを操作メモリへ書き出す |
| Harvester | HARVEST(資源・エネルギーの回収) | 射程内の最近傍ノードを自動対象化（Sensorなしでも動作可能 = 最小祖先が成立） |
| Disassembler | DISASSEMBLE（分解） | 対象は射程内のコンポーネント/残骸。自他のグループを区別しない（R7維持） |
| Storage | 資源・エネルギーの格納、TRANSFER | 同グループの他Storageへ内容物を転送できる（子個体への持たせ資源に必要） |

- Harvesterの回収物は「最小IDの空きがあるStorage」へ自動格納する
- 分離（DISCONNECT）時、各グループは自分のStorageの内容物のみを持つ。
  子個体へ資源・エネルギーを分与するには、分離前にTRANSFERで子側Storageへ移す

## 耐久度と修理（R4: 再生産コスト < 修理コスト）

- 全コンポーネントは種別ごとの最大耐久度を持つ
- 減少は決定論的:
  - 経年: AGE_INTERVAL tickごとに1減少（全コンポーネント）
  - 使用: アクション実行ごとに1減少（実行したコンポーネント）
- 耐久度0で**残骸（wreck）化**: 機能停止するが物体として残存し、接続も維持される（死重）。
  Disassemblerの分解対象であり、自発変化（崩壊）の対象でもある
- 修理: AssemblerのREPAIRアクション。対象は同グループの隣接コンポーネント
- **修理コストは修理回数ごとに逓増する**（４_v9_discussion のユーザー案を採用）:
  - 対象コンポーネントは修理回数カウンタを持つ
  - n回目の修理コスト = REPAIR_BASE_ENERGY × n ＋ 修理材料（種別ごとに定義）
  - これにより生涯総修理コストは修理回数の2乗で増加し、どのパラメータでも
    十分な回数の後には再生産が有利になる（大局的に再生産を強制、局所的には修理に利点）

## Assemblerのレシピ切替コスト（４_v9_discussion 採用）

- Assemblerは「現在構成されているレシピ」を1つ持つ（自己組み替えのメタファー）
- レシピの切替（SET_RECIPE）には RECONFIG_ENERGY と RECONFIG_TICKS がかかる
- 同一レシピの連続実行は切替コスト不要 → バッチ生産・分業（複数Assembler・種間分業）への誘因
- 最小祖先はレシピ15種類を使うため、複製1サイクルに最低15回の切替が発生する。
  切替コストの値は祖先種の成立を壊さない範囲で調整する（シナリオ検証の対象）

## エネルギーモデル

- エネルギーはStorageに格納される（Storageごとに容量上限）
- 消費: 全アクション、レシピのエネルギーコスト、Processorの実行（毎tick定額 PROC_TICK_COST）
- 供給: EnergyNode（無限総量・毎tickの流出量制限つき）からHarvesterが回収
- エネルギー放出レシピ（R4, R13）の産出はStorageへ充填される（容量超過分は消滅=熱化）
- グループ内の消費は「最小IDのStorageから順に」引き落とす（決定論）

## 資源の産出（ideas/resource_production.md からv9採用分）

- **MatterNode（有限・一点集中）**: 自然産出7物質のノード。初期量が尽きれば消滅。
  物質総量保存の唯一の初期供給源。存在量の目安は abundance（豊富/中程度/限定的/希少）に従う
- **EnergyNode（無限・固定領域・流量制限）**: 系外からのエネルギー入力（太陽光/湧出のメタファー）
- 移動資源・周期変動・勾配・流れはv9では導入しない（範囲外）
- 死骸の自発崩壊（安定性モデル）が「個体活動依存の資源発生」（方式6）を自然に実現する

## 捕食の判別可能性（４_v9_discussion の要請）

- SCANは対象の**種別コード（物質ID）**と残骸フラグを公開する
  → Disassemblerを持つグループ＝捕食能力の推定はプログラムの解釈で行う（システムは区別しない）
- 自身の耐久度は操作メモリから読み取れる
  → 「捕食（分解）を受けている」ことは耐久度の急減で検知できる
- MEMOにある「性質からのみ判別可能にする」案（種別コードを隠す）は将来の検討事項として見送る

## 自発変化の発生方式

- 対象: 安定性増加が閾値以上の分解系レシピ（現データではコンポーネント分解 RX1〜RX8 のみ）
- 毎tick、対象オブジェクトごとにシード付きPRNGで確率判定（DECAY_PROBABILITY、順序はオブジェクトID順）
- 残骸も対象（放置された死骸はやがて最下層物質に崩壊し、資源が循環に戻る）
- 温度・エネルギー密度による変調（ideas/natural_transformation.md）はv9では導入しない

## 決定論（R8復元）

- 乱数はシード付きLCG（v2/v3方式）のみ。`Math.random()` は使用禁止
- 乱数消費点: 初期配置生成、自発変化判定。消費順序は仕様で固定する
- 全フェーズの反復順序はオブジェクトID昇順
- 同一シード・同一初期状態・同一tick数 → 完全に同一の世界状態（ハッシュ比較で検証）

## v9範囲外として確認した項目

- カスタムコンポーネント仕様（「コンポーネントの仕様を決められるようにする」案）→ 影響が大きすぎるため見送り
- 種間分業を強制する仕組み（「フル仕様のキャラクターは一種では作れない」案）→
  レシピ切替コストと希少資源が自然に分業圧を生むため、強制はしない
- 情報的相互作用（R9: 遺伝子水平伝播・有性生殖の情報公開/読取）→ 3_v9_goal どおり範囲外
- 温度場・エネルギー密度場 → 範囲外（自発変化は一律確率）
