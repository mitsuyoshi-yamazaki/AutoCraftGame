# v9 ゴール定義

## v9 のゴール

ダイナミックな生態系を実現できるクラフトゲームの仕組みを作成すること。

## 達成済み要素（v9でも維持する）

v9に入る新仕様でこれらの要素が壊れないようにする必要がある。

| 要素 | 実現手段 |
|------|---------|
| 自己複製が可能 | 現在のクラフトゲーム仕様 + ProcessorのVM |
| 複製時に変異を入れることができる | 現在のクラフトゲーム仕様 + ProcessorのVM |
| 資源の有限性 | 現在のクラフトゲーム仕様 |
| 進化や変異の手法を直接提供しない | 現在のクラフトゲーム仕様 + ProcessorのVM |
| "個体"の境界をシステム的に定義しない | v8のコンポーネントおよび接続の仕様 |

## v9 で新たに達成する要素

### 1. 再生産コスト < 修理コスト

- 再生産を後押ししつつ、一時的/局所的には修理することへの利点も残すことで、生存戦略を多様化しつつ、大局的には再生産を強制する
- クラフトゲーム側の仕様であるクラフトツリーを再設計することで、同じ生産物を異なる手法で得たり、生産に対するコストを導入し、クラフトに対する戦略を多様化させる

### 2. 捕食性個体の存在

- 捕食という行為を可能にすること
- それに一定の利点を設けることで、それを選択肢に入れる
- また、それを選択しない種には、移動に対して新たな変数が導入されることで、闘争/逃走の選択圧を導入する
- 全体として、個体間の相互作用が入ることで、生態の多様化と、生態系のダイナミックさを上げることが期待できる

## v9 の範囲外

### 他個体との相互作用（捕食以上のもの）

「捕食性個体の存在」を実現するために必要最低限の相互作用は入るが、それ以上の内容（遺伝子の水平伝播、有性生殖のための情報公開/読み取りの仕組み等）はv9の対応範囲外とする。

## 実現性の評価

### 1. 再生産コスト < 修理コスト

**実現性: 問題なし**

前提として以下の仕組みが必要:
- コンポーネントに**耐久度**の概念を導入する（経年劣化 or 使用劣化）
- 劣化したコンポーネントを**修理**する手段を提供する
- 修理コストと再生産（新規組立）コストの間に差を設ける

これらはいずれもクラフトゲームの仕様として自然に導入できる。v2-v5で耐久度・代謝の仕組みは実装済みであり、技術的な障壁はない。

クラフトツリーの再設計（複数経路、コスト差）もレシピテーブルの拡張で実現可能。v8のレシピ構造（材料リスト + エネルギーコスト + 組立時間）をそのまま拡張できる。

維持すべき要素への影響:
- 自己複製: 耐久度の導入で複製手順は変わらない。修理は追加の選択肢であり、複製を妨げない
- 資源有限性: 修理にも資源を消費する設計にすれば、有限性は維持される
- 個体境界の非定義: 「何を修理するか」はプログラムが決めるため、システムが個体を定義しない原則は維持

### 2. 捕食性個体の存在

**実現性: 問題なし**

前提として以下の仕組みが必要:
- 他個体のコンポーネントを**分解**して資源を得る手段（Disassembler）
- 他個体に**接近**する手段（Actuator + Sensor による能動的移動）
- 捕食に**利点**がある（資源ノードの採掘より効率が良い、あるいは補完的である等）

v2ではScavenger種族が残骸回収で類似の行動を実現しており、概念実証済み。v9ではこれをコンポーネントレベルで分解し、プログラムの自律的判断として実現する。

捕食を「選択しない種」に対する闘争/逃走の選択圧は、能動的移動（Actuator）の導入により自然に生じる。移動が資源消費を伴う設計にすれば、「逃げるコスト」が発生し、戦略的トレードオフが成立する。

維持すべき要素への影響:
- 自己複製: 捕食の導入は複製メカニズムに影響しない。むしろ複製戦略の多様化が期待できる
- 資源有限性: 捕食は他個体の資源を再利用する行為であり、有限性の枠内で動作する
- 個体境界の非定義: 「何を攻撃するか」はプログラムが決める。システムは「分解可能」という物理法則のみ提供
- 変異の非提供: 捕食行動はプログラムの内容に依存し、システムが捕食者/被捕食者を区別しない

### 3. 達成済み要素の維持

**実現性: 問題なし**

v9で導入する要素（耐久度、Disassembler、Actuator、Sensor等）は、既存のコンポーネント・接続・VM・クラフトの仕組みの上に追加するものであり、既存機能を置き換えるものではない。以下を守れば維持可能:

- Assembler + Processor + 接続による自己複製パスを残す
- VMの命令セットとI/O体系を互換で拡張する
- 資源の総量保存則を維持する
- システムが「進化」「変異」「個体」を定義するメカニズムを入れない
