# クラフトツリー設計ノート

初版ドラフト（対話ベースで作成した spec_draft.md 初版、git履歴 `63953f2` 参照）を
機械検証可能なデータへ移す過程で行った再設計の記録。レビュー時はまず本書を読むこと。

## 1. 発見された構造的欠陥

### 1-1. X原子は無から生成できない（初版の不純物設計は原理的に不成立）

初版では「複雑な合成ほど不純物Xを生成する」ため、Xを含まない入力から
Residue(X1) を出力するレシピ（R14, R15, R20）と、Residue を S/A 原子系の物質へ
変換するレシピ（R16, R17）が定義されていた。これらは**原子種別の総量保存と矛盾する**
（Xの無からの生成、およびX→S/Aの変換にあたる）。初版で「要修正」と注記されていた
不整合11件のうち6件はこの構造問題に由来し、個別のレシピ修正では解決できない。

**採用した解決策**: Xは自然産出する低品位資源 ContaminatedMass(S2X1) としてのみ世界に入る。

- 精製 R33（高コスト）: ContaminatedMass → BaseSolid + Residue（清浄材と不純物の分離）
- 固定 R32（安価）: BaseSolid + Residue → ContaminatedMass（不純物の封入）
- dirty経路 RD1, RD2: ContaminatedMass を素材のまま使う安価なレシピ。Residue を排出する
- 「複雑な合成ほどXが出る」は「安い経路を選ぶほどResidueが溜まる」という
  戦略選択の帰結として再解釈した（システムが強制する性質ではなく経済圧）

### 1-2. 線形安定性スコアは保存則の下で退化する

初版の 安定性 = k1*S + k2*B - k3*A - k4*T - k5*I + k6*X は原子構成の線形和であるため、
原子保存が成立する**すべてのレシピで合計安定性の変化が恒等的に0**になり、
「より安定な物質へ自発変化する」という方向がどの変化にも定義できない
（test/stability.test.ts が全レシピについて機械的に確認している）。

**採用した解決策**: 階層ペナルティ（base=0, intermediate=-5, component=-15）を追加した。
「精密に組織された構造ほど壊れやすい」の表現であり、これにより:

- コンポーネント分解（RX*）のみ Δ安定性=+15 となり自発変化しうる
  → 放置された死骸・コンポーネントは自然崩壊して資源が循環へ戻る（v2の残骸吸収の後継）
- コンポーネント生成（RC*）は必ず Δ安定性<0 となり、エネルギー投入によってのみ進む
- 自発変化は独立の変換ルールテーブルではなくレシピテーブルの再利用で表現できる
  （ideas/natural_transformation.md の変換ルールテーブル案を単純化した形）

### 1-3. 裸の原子を出力するレシピが11件あった

初版のレシピの約半数は「(S1余剰)」のように物質でない裸の原子を出力していた。
物質のみが世界に存在できるという前提（requirements.md）と矛盾するため、
全レシピを**定義済み物質のみを出力する形に再均衡**した（主な手段: 化学量論の×2スケール化、
副産物の実在物質化）。

また、初版で「要修正」と注記されていなかったR3, R7, R8にも原子収支の不整合があった
（例: R3は S+1/B-1、R7/R8は A/T が不均衡）。手動レビューの検出限界を示しており、
機械検証を導入した動機そのものである。

## 3. コンポーネント一覧の確定（8種）

文書間で食い違っていた一覧（craft_tree/requirements.md: MemoryCoreあり/Harvesterなし、
0_requirement.md・1_design_discussion.md: Harvesterあり/MemoryCoreなし）は、
ユーザー判断（2026-07-13）により**8種（両方採用）**で確定した。

- Assembler, Disassembler, Processor, MemoryCore, Actuator, Sensor, Harvester, Storage
- ただし**祖先種の必須構成に MemoryCore は含めない**（v8同様、Processor単体でプログラム保持可能。
  MemoryCoreは拡張記憶であり、複製に必須の7種構成を小さく保つ）

原子構成は機能と原子の役割が対応するよう設計した（単調性の方針）:

- 情報処理系（Processor I4, MemoryCore I3, Sensor I1）… I需要 = 希少資源ボトルネック
- 反応系（Assembler A1C1, Disassembler A3C1）… Disassemblerの高Aは「壊す方が乱暴」の表現
- 運動系（Actuator T1A1, Harvester T1A1）… T+A
- Storage（S6B1）… 純構造・コンポーネント中最安定

## 4. エネルギーコスト設計

- 放出（負値）レシピは R4(-10), R13(-5) の2件のみ。
  **物質が閉じるどの循環も合計エネルギーが正**であることをテストで固定
  （エネルギーポンプ=無限機関の禁止。負値レシピを追加する際は対応する循環テストを追加すること）
- 相対関係のみ設計した暫定値: 最下層変換 5〜25 ＜ 中間合成 20〜30 ＜ コンポーネント生成 80〜150
- 触媒版は通常版の約半額（R1c: 15→8, R27c: 30→15）。触媒獲得コストとのトレードオフ
- dirty版は清浄経路（精製30E＋通常合成）より大幅に安い（RD1: 10 vs 45相当）。
  Residue蓄積との交換であり、クラフト戦略の多様化（v9ゴール1）の主要な源

## 5. 生産コスト解析の含意

`npm run craft:report` による正準経路（貪欲展開）の上界:

- **コンポーネント一式（8種×1）= エネルギー1405・39工程・InfoSeed×9 ほか**
- 祖先種は自己複製1回あたり約40回のレシピ実行＋資源回収＋組立＋プログラム複写を行う。
  v8のレプリケータ（184命令・2コンポーネント）と比較して工程数は約20倍であり、
  **祖先種プログラムの複雑さが最大のリスク**という認識は維持
  （Step 2 で複製シナリオの机上検証を行い、必要ならクラフト実行の粒度を調整する）
- 多くの中間レシピが×2単位で生産されるため、2体同時生産は1体あたりコストが下がる
  （スケールメリットが自然に存在する。多産戦略への隠れた誘因）
- Processor分解（RX1）は InfoSeed 等の情報系素材を返す。希少資源Iの最効率な入手経路が
  「他個体のProcessorの分解」になりうる = **捕食に構造的な利点がある**（v9ゴール2に接続）

## 6. レビュー観点（ユーザーへの確認事項）

1. **雰囲気・それらしさ**: 物質名、レシピの意味づけ（概要文）に違和感がないか
2. **X設計の変更**: 「複雑な合成ほどX生成」→「安い経路ほどResidue蓄積」への再解釈を許容するか
3. **安定性モデル**: 階層ペナルティ方式と「自発変化=レシピ再利用」の単純化を許容するか
4. **分解出力**: コンポーネント分解が最下層へ格下げされる設計（中間物質は返らない）の強度
5. **数値**: エネルギー暫定値・安定性係数・閾値（いずれもシミュレータ実装後に実測調整予定）
6. **自然産出セット**: 7種（うちX入口はContaminatedMassのみ）の妥当性
