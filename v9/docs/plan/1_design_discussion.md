# 設計議論の記録

v8からv9への仕様拡張にあたり、インタビュー形式で設計判断を収集した記録。

## 確定事項

### 位置モデル

- ワールド座標系は**連続座標を維持**（六角グリッドではない）
- グループ内のコンポーネントは**すべてグループのワールド座標を共有**する（v8と同様）
- グループ内ローカル座標は現時点で不要（利用しない）

### 辺アドレッシング

- コンポーネントの辺は**インデックス 0〜5** で指定する
- 辺番号による指定は**補助的な手段**として、現行のローカルID方式と**併用**する
  - ローカルIDベースのアクセス（v8の `0x1005` 等）は維持
  - 加えて、辺インデックスによるアクセスが可能

### 衝突判定

- コンポーネント（グループ含む）の衝突は**円近似**で判定する
- 近似円の直径と中心は、**接続状態が変わった際に再計算**する
- 計算は**パフォーマンス最優先**で、精密な近似は不要
- 衝突の処理は**v3-v5のバネ反発方式**を採用する
  - `overlap = (radiusA + radiusB) - distance(A, B)`
  - `repulsion = overlap × COLLISION_STIFFNESS`（重なりに比例する反発力）
  - 速度・摩擦を含む物理積分で位置更新
- コンポーネント以外のオブジェクト（資源ノード、エネルギー等）は衝突しない

### GroupObject

- v8の GroupObject 概念を維持する
- 六角形の辺情報（どのコンポーネントがどの辺に接続しているか）をグループ内で管理

## 未決定事項（議論中断）

以下の項目は質問を提示した段階で議論を中断した。

### Q5: 物理モデルの変更

v8のランダム移動を、v3-v5式の力ベース物理に戻すかどうか。

- **(a)** v3-v5式に戻す: 速度・力・摩擦を持ち、Actuatorが推進力を発生。ランダム移動は廃止
- **(b)** ランダム移動を維持しつつ、衝突だけバネ反発で位置補正

バネ反発を導入する以上、(a) の可能性が高い。Actuatorの導入とも整合する。

### Q6: 辺スロットの対称性

コンポーネントAの辺2にBが接続されたとき、B側の辺スロットはどう決まるか。

- **(a)** 対面辺の自動割当（Aの辺2 → Bの辺5）
- **(b)** 双方独立指定
- **(c)** 受け手側は空き辺の自動割当（最小番号）

ローカル座標がなく全メンバー同位置のため、辺方向に物理的意味はない。

### Q7: ASSEMBLE時の辺指定

v8では `connection_target_id` のみ指定していた。v9では辺インデックスの指定をどう組み込むか。

- 接続元/先の辺を明示指定するか
- 自動割当に任せるか

### Q8: 新コンポーネント群の役割分担

v8のAssemblerが担っていた「材料吸収 + 組立 + 接続管理」を分離する。確認が必要な点:

| コンポーネント | 想定される役割 |
|---|---|
| **Assembler** | 組立のみ（材料はStorageから取る？） |
| **Processor** | プログラム実行（v8と同様） |
| **Actuator** | 移動の推進力を発生 |
| **Sensor** | 周囲のオブジェクトを探知（SCANの担い手） |
| **Harvester** | 周囲の資源・エネルギーを回収 |
| **Disassembler** | 死骸や他コンポーネントを分解して資源に変換 |
| **Storage** | 資源とエネルギーを格納する倉庫 |

未確認の論点:
- Assemblerは自力で材料吸収しなくなるのか（Storageから消費する方式か）
- Harvesterが回収した材料の格納先（自身の一時保持 or 同グループ内Storageへ自動格納）
- Disassemblerの対象となる「死骸」の概念（v8には存在しない。コンポーネントの破壊・死亡メカニズムの導入が必要か）

### 未着手の論点

以下はまだ議論に入っていない。

- **資源とレシピの設計**: 新資源の種類と性質、レシピの段数・分岐
- **エネルギーモデル**: 各コンポーネントのエネルギー消費、Storageとの関係
- **操作メモリの再設計**: 新コンポーネント群それぞれの操作メモリレイアウト
- **I/Oアドレスの再設計**: 辺インデックスベースのアクセスのI/Oマッピング
- **ゲームループの再設計**: 物理モデル変更に伴うフェーズ構成
- **自己複製シナリオ**: 7コンポーネント構成での複製手順
- **定数設計**: 衝突パラメータ、六角形サイズ等
