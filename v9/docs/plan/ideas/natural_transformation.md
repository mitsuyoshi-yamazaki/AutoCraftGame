# 自然な物質の変化

## 概要

Assembler/Disassemblerによらない、環境条件に基づく物質の変換を導入する。
コンポーネントなどの複雑な生成物が自然に分解したり、特定条件下で物質が合成されたりする仕組み。

## 動機

- 耐久度の概念と組み合わせて「再生産コスト < 修理コスト」の実現を後押しする
- 資源循環を自然にする（分解された高次物質が低次物質に戻る）
- 環境条件への適応という新たな選択圧を導入する

## 変換の例

- エネルギー密度の高い場所に置かれた化合物が分解する
- コンポーネントなどの複雑な生成物は、より低いエネルギー密度で分解する
- 自然に発生しうる条件で合成される物質がある

## 実装方式: グリッドベースの環境場 + 変換ルールテーブル

### 環境場の計算

ワールドを粗いグリッドに分割し、tick開始時に各セルの環境値を集計する。

```
エネルギー密度[cell] = セル内のEnergyObjectのamount合計 / セル面積
```

計算量はO(オブジェクト数)。全オブジェクトを1回走査してセルに振り分けるだけ。
グリッド解像度は粗くて良い（近似が前提）。

### 変換ルールテーブル

単体分解の例:
```
{ input: 'Circuit', condition: energyDensity > 50, output: ['Crystal', 'Crystal'] }
{ input: 'Metal',   condition: energyDensity > 80, output: ['Ore'] }
```

合成の例:
```
{ input: ['Ore', 'Crystal'], condition: energyDensity > 30, output: ['Metal'] }
```

- 単体分解: オブジェクトが属するセルの環境値を参照し、閾値超過で変換。O(対象オブジェクト数)
- 合成: 同一セル内に入力材料が揃っているかをセル単位で判定。全ペア比較を回避

### ゲームループへの組み込み

1フェーズ追加する:

```
1. Processor実行
2. Component action phase
3. 環境変換phase ← 追加
   3-1. グリッドに環境値を集計
   3-2. 各オブジェクトの変換ルールを判定・適用
4. 物理（移動・衝突）
5. 境界補正
6. tick++
```

### パフォーマンス評価

| 処理 | 計算量 | 備考 |
|------|--------|------|
| グリッド集計 | O(N) | 全オブジェクト1回走査 |
| 単体分解判定 | O(M) | 対象種別のオブジェクトのみ |
| 合成判定 | O(セル数 × セル内材料種別数) | セル単位でまとめるため安価 |

オブジェクト数が数千程度なら、tickあたりの追加コストは無視できる。

### 安定度による統一

各物質に安定度(stability)を持たせると、ルールを統一的に記述できる。

- 原材料（Ore, Crystal）: 安定度 高 → 高エネルギーでも分解しにくい
- 中間生成物（Metal, Circuit）: 安定度 中
- コンポーネント: 安定度 低 → 比較的低いエネルギー密度で分解

分解閾値 = 定数 / 安定度、のような関係にすればパラメータ調整も容易。
