# v9 総括 — 目的達成の評価と、必要な要件・仕様の還元

本書は、委任された調査タスク「プロジェクトの目的を達成するにはどのような要件・仕様を
設定するべきかを明らかにする」への最終回答である。v9の実装と実験01〜08を根拠とする。

## プロジェクトの目的（再掲）

- 進化手法そのものを人間のプレイヤーがプログラム可能な、十分に柔軟で拡張性のある、
  一貫した世界を提供すること
- そのために: 自律的に自己複製/自己拡張/自己修復を行うゲーム内キャラクターが実現可能で、
  その祖先種（最低限、自己複製と進化を行う）を人間が構築可能であること
- 制約: 進化手法や突然変異の手法をシステム上提供しない

## 結論

**目的は達成可能であることが実証された。** v9は上記を満たす世界の一つの具体化であり、
目標が掲げる**自己複製・自己拡張・自己修復の3モードすべて**を別々の種（プログラム）として、
さらに捕食種を、同一の物理法則の上でプログラムとして実現・共存させることを実データで確認した。

## 目標の3モード（自己複製/自己拡張/自己修復）の達成

| モード | 種 | 実証 |
|--------|-----|------|
| 自己複製 | [ancestor.ts](../src/programs/ancestor.ts) | 子個体を組み立て起動（実験01） |
| 自己拡張 | [expander.ts](../src/programs/expander.ts) | 自身に部品を接続し4→8部品に成長（実験04） |
| 自己修復 | [repairer.ts](../src/programs/repairer.ts) | 器官をREPAIRで維持し延命（実験04） |

3モードは同じ物理機構（ASSEMBLE・接続・REPAIR）の異なる使い方であり、システムは
これらの概念を持たない。「複製/成長/修復」はすべてプログラムの意図である。

## 目的を達成するために必要だった要件・仕様（本タスクの回答）

v1〜v9の全過程から抽出した、「進化がプログラム可能な一貫した世界」に**本質的に必要**な要素。

### 1. チューリング完全なプログラムを個体が持ち、それが遺伝物質であること

- 個体の振る舞いを決めるのはデータではなく**プログラム**（v9: 16bit von Neumann VM）でなければ、
  変異が表現力を持たない（v1のJSONルールは1バイト変更で破綻し、変異に耐えなかった）
- そのプログラムが**複製される実体（ゲノム）**であること。v9ではProcessorのpmem全域が
  複製対象であり、変異はその上のビット操作として表現される

### 2. コピーの手段だけを提供し、コピーの忠実度を規定しないこと（R6の具体化）

- システムは「他個体のメモリへ書き込む」I/Oを提供する（v9: 0x2000系pmem書込）。
  **完全にコピーするか、改変してコピーするかはプログラムが決める**
- これが v7/v8 の袋小路（原子的コピーで変異ゼロ、あるいは自己書き換え不能）を抜ける鍵だった。
  v9は「忠実コピーはデフォルト、変異はオプトイン」という設計で R2×R6 を両立させた
- 補足: v8の「AUTO増分は書込ドロップ時も進行する」性質も維持した。これは意図せぬ変異源
  （穴あきコピー）だが、プログラムが対処すべき物理的リアリティとして残す

### 3. 原子種別ごとの物質保存（最もシンプルで確実な淘汰圧）

- 各原子種の世界総量が保存されること。これが「無限増殖の不可能性」を数学的に保証し、
  資源獲得競争＝淘汰圧を生む（v9: 検証器で全レシピの原子保存を機械証明、会計で実行時検証）
- クラフトツリーは「原子保存付きグラフ設計問題」として設計する（循環経路の保証、デッドエンドの排除）
- 希少資源（v9: InfoSeed）が高度コンポーネント（Processor）のボトルネックになるよう配置すると、
  枯渇→再利用（分解・捕食）への圧が自然に生じる

### 4. 全活動に副作用（コスト）があること

- エネルギー消費、劣化、不要な副産物。これらがなければ「動く動機」が消え、
  エネルギーノードの隣で不死になる問題（MEMO.md）が起きる
- 特に**再生産コスト < 修理コスト**（逓増修理）が世代交代を強制し、進化のサイクルを回す

### 5. 個体をシステムが定義しないこと（R7）

- 「キャラクター」「種」「個体」という単位をシステムが持たないこと。あるのは最小の物理単位
  （コンポーネント）とその接続だけ。何を「自分」とみなし何をコピーするかはプログラムが決める
- これにより、寄生・共生・多細胞化・分業といった構造が、システム変更なしにプログラムとして創発しうる

### 6. 決定論（R8）

- 再現性は実験科学の前提。シード付きPRNGのみを使い、全フェーズの反復順序を固定する
- これにより変異体の運命を再現・比較でき、「同じ初期条件から異なる進化史」（seedSalt）も制御できる

### 7. ヘッドレスCLIと機械検証

- 進化は長時間スケールの現象であり、UIなしで高速実行・大量試行できること（v9: `npm run sim`）
- 世界の不変条件（原子保存・決定論・エネルギーポンプ禁止）をテストで守ること。
  仕様と実装の乖離を防ぐ（v9: データ駆動のクラフトツリー＋同期テスト）

## v9が示した「進化のプログラマビリティ」の広がり

同一のv9世界の上で、プレイヤー（AI）は以下をすべて**プログラムとして**書き分けられる:

- 自己複製する種・自己拡張する種・自己修復する種（実験01・04。目標の3モード）
- 変異率・粒度の異なる複製戦略、中立変異を溜める種 vs コード枢要部を守る種（実験03）
- 捕食する種・される種（実験02）
- **定住種（クレードル依存・省エネ） vs 移動種（探索採取で世界を移動・複製し局所枯渇から脱出。実験06）**。
  両者を同じ世界で競争させると、確率的な勝敗と生態的トレードオフが創発する（実験07）
- **同じ能力構成のまま繁殖能力の異なる種**（実験08）。器官を摩耗する前に修理し、修理材料を
  子に持参金として渡す個体は、移動複製種の2〜3倍生きて2〜7倍の子を残した

さらに、生態系の**舞台**（祖先の数・配置・距離・資源量・変異率・捕食者の有無）は config として
プレイヤーが構成でき、そこから決定論的に生態動態が展開する（実験05）。

- 未実装だが同じ機構で書けるもの: 自己書き換えによる表現型可塑性、有性生殖（複数親メモリの混合）、
  寄生（v8ハイジャッカーの再現）、分業（レシピ切替コストが誘導）

システムはこれらのいずれも「知らない」。提供するのは物質・エネルギー・力・接続・
読み書きI/Oという一貫した物理法則だけである。

## 実験05が明らかにした空間生態の前提

複数コロニーの競争・空間実験（実験05）から、重要な設計的知見が得られた:

- **定住種では空間的競争が存在しない**。各コロニーは自分のクレードルに留まり相互作用しないため、
  ワールドを広げても資源を増やしても動態は不変だった
- 資源が潤沢なら加齢が、希少なら局所枯渇が動態を支配し、いずれも空間と無関係。
  定住種は局所資源を使い切ると移動できず必ず絶滅する
- したがって「空間を広げて競争不利の種を延命させる」古典的な空間生態は、**移動種を前提とする**。
  これは移動能力（Actuator）の適応価値を定量的に裏づけた

**実験06でこの移動種を実装し、局所枯渇からの脱出を実証した**（コア変更不要でv9で実現。
pmemを1024→4096へ拡大したのみ）。移動種は資源を探索採取して世界中に拡散し（個体間最大93単位、
ほぼ世界の端から端）、定住種が生誕地半径15単位に留まるのと対照的だった。

**実験07で移動種と定住種を同じ有限資源の世界で競争させ、真の空間競争を観察した**。
勝敗は確率的で（初期条件依存）、移動種が定着すると世界中の散在資源を使って定住種を凌駕し、
競争排除することもあった（5シード中3つで移動種が優勢、うち定住種を絶滅させた例も）。
一方2/5では定住種が勝つ。**支配的戦略は存在せず**、移動（世界全体の資源にアクセスできるが
高コストで凍結しやすい）と定住（安価で確実だが局所に縛られる）という生態的トレードオフが
成立した。これで進化の勾配（定住↔移動）の両端が同じ世界のプログラムとして実現され、
両者の空間競争の帰結がプログラムと初期条件の相互作用として創発することが示された。

## 実験08が明らかにした「繁殖能力の正体」

実験06の移動複製種は繁殖が続かず、その原因を「移動はエネルギー的に高コストだから」と
考察していた。実験08で器官ごとの摩耗を実測したところ、**死因はエネルギーではなくSensorの摩耗**
だった。Sensorは経年劣化に加えSCAN 1回ごとに1摩耗するため、探索採取を続ける個体では
約0.42/tickと突出して速く削れ、最初の採取フェーズ1回（約2500tick）で残骸になる。
探知を失った個体が資源もエネルギーも見つけられず彷徨した結果が、観察されていた
「エネルギー枯渇による凍結」だった。

同じ6部品・同じ物理法則・同じ環境のまま、(1) 探索の1周ごとに全器官の耐久度を点検しREPAIRする、
(2) そのための修理材料をサイクル先頭のキット工程で作る、(3) 子に修理材料を持参金として渡す——
の3点だけを足した種は、祖先個体の寿命が2.4〜3.3倍（6,980→22,820 tick）になり、
40000tickで生まれた個体数が2→6、1→7に増えた。

これは実験04の結論（修理コストは回数の2乗で効くので自己修復は再生産に勝てない）と矛盾しない。
修理回数は17に達し1回720エネルギーとStorage容量に迫っていたが、**コストの壁に当たる前に
子へ世代が渡る**ため、維持は繁殖までの時間を買う手段として機能した。さらに、修理材料が
希少資源（InfoSeed）を要するため、この戦略は**親子2世代にまたがってはじめて成立する**
（生まれたばかりの個体は自力で材料を揃える前に感覚器を失う）。

淘汰に直結する形質（繁殖能力）が、システムのパラメータではなくプログラムの書き方——
点検を差し込む位置と持参金の中身——で数倍変わることが、ここで示された。

さらに、器官を維持して個体の寿命の壁を越えると、**次は世界の側の壁**が現れた。
個体群はt=30,000前後でエネルギー収支が破綻して全滅する。原因は逓増する修理費に加え、
(a) 2tickごとにSCANを撃ち直す——推進が加速し切らないうちに向きを変えるので、ほとんど進まないまま
1回5エネルギーとSensor摩耗を払う——探索、(b) 修理が排出する摩耗材の捨て置き、(c) 経路上の
分解物の無視、であった。弾道的な移動（接近4tick・彷徨12tick）、摩耗材の回収、射程内の有用物の
拾い上げ、在庫駆動の工程省略を入れると、同時個体数のピークは15→35、累計誕生は14→92になり、
絶滅はt=37,500からt=150,000へ遠のいた。

そこで最後に残るのは**世界の希少原子の総量**である。情報原子(I)は世界に1,209個しかなく、
死骸が散るほど回収が追いつかない。個体数の上限を決めるのは、もはや寿命でも修理費でもなく、
物質循環をどこまで閉じられるかになった。

## 残る課題（今後のバージョンへ）

1. **R9（情報的相互作用）の本実装**: 有性生殖・遺伝子水平伝播のための情報公開/読取プロトコル。
   v9は近接pmemアクセスの基盤のみ
2. **複数の移動種のニッチ分化**: 移動 vs 定住の空間競争は実証した（実験07）。次は移動種同士に
   異なる資源選好・移動戦略を持たせ、ニッチ分化・共存を観察する。繁殖持続性は実験08の
   器官維持でほぼ解決した（founder freezeの籤が大きく減る）ので、長命移動種同士の競争として
   実施できる。維持しない移動種との直接競争も、選択圧の実証として残っている
3. **長期の開放的進化**: 数十万tick規模で、変異の蓄積が新しい表現型（新しいニッチの獲得）を
   生むかの検証。現状は「変異が生存する」までを確認
4. **パラメータの本調整**: エネルギー・耐久・変異率は暫定値。生態系が最も豊かになる領域の探索
5. **観察ツール**: 系統樹の可視化、表現型の分類、GUI

## 一文で

**進化手法をシステムが一切提供せず、物質保存・力学・チューリング完全なプログラム・
コピーI/Oという一貫した物理法則だけを与えれば、自己複製・変異・淘汰・捕食は
すべてプレイヤーのプログラムとして実現でき、その祖先種はAIが構築可能である** —
これがv9で実証された、本プロジェクトの目的に対する答えである。
