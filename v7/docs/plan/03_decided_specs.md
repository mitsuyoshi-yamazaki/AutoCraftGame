# v7 決定済み仕様

本文書は v7 の実装に先立ち、議論を通じて決定された仕様をまとめる。
未決定の事項は `02_open_questions.md` を参照。

---

## 1. 世界モデル

### 1-1. 物体の種類

v7 の世界にはシステム上の「キャラクター」概念は存在しない。世界に存在するのは全て**オブジェクト**であり、以下の種類がある。

| 種別 | 説明 | v7.0.0 |
|------|------|--------|
| コンポーネント | Assembler, Processor 等。それぞれが独立した物体 | 含む |
| 中間生成物 | Metal, Circuit。それぞれが独立した物体 | 含む |
| 原材料 | Ore, Crystal。それぞれが独立した物体 | 仕様上存在するが、初期状態に含めるかは任意 |
| エネルギー | エネルギー量を持つ物体 | 含む |
| 資源ノード | Ore/Crystal の発生源 | v7.0.0 には含めない（将来実装） |
| エネルギーノード | エネルギーの発生源 | v7.0.0 には含めない（将来実装） |

### 1-2. エネルギーおよび原材料オブジェクトの仕様

- エネルギーオブジェクトは**格納量**（energy amount）を持つ
- 原材料オブジェクトは**資源量**（resource amount）を持つ
- 周囲のコンポーネントに吸収されると、その分だけ格納量/資源量が減る
- 格納量/資源量が 0 になったらオブジェクトは世界から消滅する
- オブジェクトの大きさは格納量/資源量に比例した面積の円形で表現する

### 1-3. 中間生成物およびコンポーネント

- 1 つの中間生成物が 1 つのオブジェクトとして世界に配置される
- 1 つのコンポーネントが 1 つのオブジェクトとして世界に配置される

### 1-4. オブジェクトの統一的表現

実装上、世界に存在する全オブジェクトは**統一された型（interface）**として扱う。個別の種別は具象型として表現する。

```
WorldObject (interface)
├── ComponentObject (Assembler, Processor, ...)
├── MaterialObject (Ore, Crystal, Metal, Circuit)
└── EnergyObject
```

### 1-5. 資源の発生メカニズム

v7.0.0 では、エネルギーおよび資源は**初期に配置されたもので全て**である。再生メカニズムは v7.0.0 には含めない。

将来的には以下を実装する：
- コンポーネントや中間生成物の分解
- エネルギーノード / 資源ノードからの供給

## 2. 物体の移動

### 2-1. ランダム移動

- 全オブジェクトは毎 tick ランダムに移動する
- 「力場」ではなく、各オブジェクトが個別にランダムな方向・距離を移動する
- 移動は**決定論的でなくてよい**（Math.random 等の使用を許容）
- 複数のオブジェクトに一様に力を与える「場」は存在しない

### 2-2. 衝突

- v7.0.0 では衝突判定を**省略する**
- 全てのオブジェクトは互いに衝突しない（重なりを許容）
- 世界を囲う壁にめり込んだ場合は、近くの世界の領域内に位置を補正する

### 2-3. オブジェクトの向き

- オブジェクトは向き（orientation）を持つ
- v7.0.0 では向きを変える仕組みはない
- 全てのオブジェクトの向きは実装上の角度の原点方向（0度 = 右方向）で固定

---

## 3. 近接（proximity）

### 3-1. 定義

- 2 つのオブジェクト間のユークリッド距離が **近接距離（proximity range）** 以下であるとき、「近接している」とする
- 近接距離は全アクション・全コンポーネント種別で**一律**

### 3-2. 近接の用途

- Assembler が材料・エネルギーを「周囲から取り込む」範囲
- Processor が他コンポーネントに「アクセス可能」と判定される範囲
- 生成物の放出位置の基準

---

## 4. コンポーネント共通仕様

### 4-1. 操作メモリ

各コンポーネントは**操作メモリ（operation memory）**を持つ。これはそのコンポーネントを操作するための外部インターフェースである。

- コンポーネント種別ごとに**固定長**
- 規模は v6 のコンポーネント操作用メモリ領域（I/O スロット）と概ね同等
- 操作メモリは以下の領域を含む：
  - **パラメータ領域**: アクションの引数を書き込む領域（例: Assembler のレシピ設定）
  - **アクショントリガー領域**: 実行するアクション種別を書き込む領域
- アクショントリガー領域は**次 tick で自動的にクリア**される

### 4-2. アクション実行プロトコル

外部の Processor がコンポーネントにアクションを実行させる手順：

1. Processor が近接コンポーネントのアクセス可能一覧を取得する
2. 対象のローカル ID を指定して操作メモリにアクセスする
3. パラメータ領域に引数を書き込む
4. アクショントリガー領域にアクション種別を書き込む → アクションがトリガーされる

### 4-3. 操作メモリの可読性

- 外部の Processor は対象コンポーネントの操作メモリを**全て読み取り可能**
- 例: Processor は Assembler の操作メモリを読み、レシピが設定済みかどうかを確認できる
- 将来的にはアクセス権限機能を追加する

## 5. コンポーネント仕様

Assembler および Processor の詳細仕様（操作メモリレイアウト、I/O アドレスマッピング、レシピテーブル等）は **`04_component_specs.md`** に記載する。

ここでは要点のみ記す。

### 5-1. Assembler

- レシピは操作メモリ内のレシピ設定領域に保持される。表現は**生成物の種類**（レシピ ID）
- 必要な材料はシステム側の固定レシピテーブルから引く
- 生成可能なもの: 中間生成物（Metal, Circuit）およびコンポーネント（Assembler, Processor）
- レシピ未設定の Assembler は何もしない
- ASSEMBLE トリガー後: 材料回収（無期限待機）→ 組立（n tick）→ 前方放出

### 5-2. Processor

- 内蔵メモリ: 1024 ワード（MemoryCore 1 個分）
- 命令セット: v5/v6 の 16bit 命令セット（CHECKPOINT は廃止）
- 操作メモリ: 実行/停止フラグ。他 Processor から書き込んで起動する
- 初期状態は停止。他 Processor が起動すると毎 tick 最大 1000 命令を実行
- 別 Processor のプログラムメモリを読み書き可能（オートインクリメント付き）

### 5-3. レシピテーブル

v6 のレシピを引き継ぎ、Assembler の統一レシピとして扱う:

| レシピ ID | 生成物 | 材料 |
|-----------|--------|------|
| 1 | Metal | Ore × 2 |
| 2 | Circuit | Crystal × 2 |
| 3 | Assembler | Metal × 2, Circuit × 1 |
| 4 | Processor | Circuit × 3 |

レシピ ID 0 は未設定を表す。

## 6. Processor 仕様

詳細は `04_component_specs.md` に記載。要点のみ記す。

### 6-1. 内蔵メモリ

- 1024 ワード（MemoryCore 1 個分）
- 外部 MemoryCore は v7.0.0 には存在しない

### 6-2. VM 命令セット

- v5/v6 の 16bit 命令セットを**そのまま流用**。I/O アドレス空間のみ v7 用に再設計
- CHECKPOINT は**廃止**

### 6-3. 実行モデル

- 操作メモリに実行/停止フラグ。初期状態は停止
- 他 Processor から起動されると毎 tick 最大 1000 命令を実行

### 6-4. メモリアクセス

- 近接する別 Processor のプログラムメモリを読み書き可能（I/O 空間経由、オートインクリメント付き）
- 複数 Processor が同一対象に書き込みは**許容**（実行順による後勝ち）
- 実行中の Processor への書き込みも**許容**

### 6-5. 複数 Processor の実行順

- 同一 tick ではオブジェクト ID 順等の実装順で先後が決まる
- 先に実行された Processor の書き込みは後続から即座に観測可能

## 7. v7.0.0 のコンポーネント種別

**Assembler と Processor の 2 種のみ。**

v6 に存在した Frame, Actuator, Sensor, Harvester, Charger, Disassembler, MemoryCore は v7.0.0 には存在しない。

## 8. 自己複製の仕組み

### 8-1. 近接維持

- 近接を維持する仕組みは**設けない**（偶然の近接のみ）
- 十分な初期資源で成立を図る

### 8-2. 変異

- メモリコピーは**完全にノイズなしのコピー**
- システム的な変異メカニズムは存在しない
- 以下の「自然な」変異が発生しうる:
  - メモリコピー完了前に Processor 間の距離が離れ、コピーが不完全
  - 稼働中 Processor へのメモリ書き込みによる予期せぬ動作

## 9. I/O モデル

I/O アドレスマッピングの詳細は `04_component_specs.md` セクション 5 に記載。

要点:
- **自身の状態** (0x0000〜): 位置、tick
- **自身の操作メモリ** (0x0100〜): 自 Processor の操作メモリ（SCAN パラメータ・結果を含む）
- **外部操作メモリアクセス** (0x1000〜): ローカル ID + オフセット指定で読み書き（オートインクリメント付き）
- **外部 Processor メモリアクセス** (0x2000〜): ローカル ID + アドレス指定で読み書き（オートインクリメント付き）

## 11. 実装ベース

**v6 をコピーし、vm/ と ui/ 基盤を残して src/ の大部分を新規作成する。**

| 流用 | 新規作成 | 削除 |
|------|---------|------|
| vm/ (vm.ts, opcodes.ts, assembler.ts, compiler/) | World 型、simulation ループ | Character 関連全て |
| ui/ 基盤 (Renderer, HTML/CSS) | オブジェクトモデル、actions | reflexes, corruption, ground |
| テストフレームワーク設定 | io (I/O ハンドラ) | recipes の大部分 |

| | ランダム移動 | primitives, seeds |
