- 最終的な目標は、任意の手法の進化を行えることである。
- このため、自己複製、変異、進化手法はシステム的に提供しない
- 同様の理由で、進化に対して制約を設けてしまうため、抽象的（primitiveでない）な機能を提供する機能の存在は望ましくない
  - v6までのコンポーネントはまさに抽象的な機能であるが、これは人間が祖先種を実装するうえで必要な抽象化であるとして許容している
    - これらの抽象的機能は、遠い将来（年単位）には、よりprimitiveな機能の集合として表現していきたい
- v7では、v6とは異なる仕組みによる制御プリミティブの実装と、それによる自己複製の実現を目標とする
  - 祖先種を人間がプログラミング可能かどうかという視点はこのバージョンでは無視して良い
- v6の制御プリミティブは、本ゲームの大目標の達成の道筋から、以下の点でずれていたと考えている
  - 抽象機能の提供
    - 制御プリミティブ自体（コンポーネントであるため、抽象機能であること自体は問題ではないが、より低次のコンポーネントの組み合わせで容易に実現できるのであればそうするべき）
    - 複製時のAssemblyTemplateの自己参照
    - システム的に提供される複製時の変異
- v7の制御プリミティブの仕様
  - 概要
    - 最小構成の単機能のProcessorが制御プリミティブとして機能する
  - 仕様（概要）
    - Assemblerは設定されたレシピをもとに、周囲の原材料とエネルギーを取り込み、材料が充足すると生成物を出力する
    - ProcessorはレジスタとMemoryCoreを持たずとも、単体で最低限動作するスペックを持つ
    - 物体をランダムに移動させる力場がある
    - 採掘された資源やエネルギー、中間生成物も、世界に放出されればひとつの物体として振る舞う
  - 想定する振る舞い
    - 初期状態
      - 様々な力場が設定されており、オブジェクトが様々に移動し衝突し合う状況が設定されている
      - 中間生成物とエネルギーが無数に漂っている
      - 以下の単体のコンポーネントが存在する
        - a. Assemblerをレシピに設定したAssembler
        - b. Processorをレシピに設定したAssembler
        - c. AssemblerにAssemblerのレシピを設定し、Processorに自身のメモリ内容をコピーするProcessor
        - d. AssemblerにProcessorのレシピを設定し、Processorに自身のメモリ内容をコピーするProcessor
    - 振る舞い
      - a, bは周囲の中間生成物とエネルギーを取り込み、レシピに設定された以下のコンポーネントを生成する
        - e. レシピが設定されていないAssembler
        - f. メモリ内容が空のProcessor
      - cはe. レシピが設定されていないAssemblerにAssemblerのレシピを設定し、f. メモリ内容が空のProcessorに自身のメモリ内容をコピーする
      - dはe. レシピが設定されていないAssemblerにProcessorのレシピを設定し、f. メモリ内容が空のProcessorに自身のメモリ内容をコピーする
    - 結果
      - これにより、資源とエネルギーを使い果たすまで、a, b, c, dによる互いの生産が続く
  - 仕様（詳細）
    - キャラクター
      - 今まで「キャラクター」として定義されていた、システム上の区分はなくなる
      - キャラクターに設定されていた、代謝によるエネルギー消費や、durabilityの概念も無くなる
    - コンポーネント
      - コンポーネントの持つアクションは、実行時間を持つようになる
        - 例：AssemblerがASSEMBLEを行うにはn tickかかり、ASSEMBLEをトリガーしたのちn tick後に生成が完了する
      - コンポーネントにアクションを指定するため / アクション結果を格納するメモリ領域はコンポーネント側に存在する
      - コンポーネントが消費するエネルギーや資源は、それらがコンポーネントの周囲に存在したら取り込まれる
        - 例：AssemblerがASSEMBLEをトリガーされると、使う原材料としての資源と、そのアクションコストのエネルギーを周囲から回収し始める。不足がなくなるとASSEMBLEが実行され、実行が完了したら生成物を放出する
        - 例：Processorが別のAssemblerやProcessorへアクセスする際も、対象が一定距離内にいる必要がある（将来的にはコンポーネント同士の接続機能を実装し、個体として一体化できるようにする）
