# プログラム変異の分析

## a. 静的分析（実行せずに確認できる内容）

### プログラムサイズ

`generateReplicatorProgram` が生成するプログラム（c: recipe=3, d: recipe=4）のサイズ:

| 項目 | 値 |
|------|-----|
| プログラムサイズ | **120 ワード** (1024 中、11.7%) |
| Phase 1 (Assembler探索・設定) | 54 ワード |
| Phase 2 (Processor探索・コピー・起動) | 66 ワード |
| 未使用領域 | 904 ワード (すべて 0) |

※ スタックポインタは使用していない（PUSH/POP/JALR なし）。レジスタ r0-r6 のみ使用。

### 命令実行数

各操作に必要な命令数（ベストケース: 対象がSCAN結果の先頭にある場合）:

| 操作 | 命令数 |
|------|--------|
| Phase 1: SCAN + idle Assembler 探索 + レシピ設定 + トリガー | **32** |
| Phase 2: SCAN + stopped Processor 探索 | **18** |
| Phase 2: コピーセットアップ (PMEM_TID, PMEM_ADDR, ループ初期化) | **8** |
| Phase 2: メモリコピーループ (4命令 × 1024回) | **4096** |
| Phase 2: 起動 (run_flag=1) + HALT | **10** |
| **合計** | **4164** |

SCAN結果の N 番目に対象がある場合、1回のスキップに約 8 命令追加。最悪ケース（8結果すべてスキップ）でも +56 程度。

### tick あたりの命令実行数

| パラメータ | 値 |
|-----------|-----|
| `instructionsPerTick` | **10,000** |
| プログラム実行命令数 (ベストケース) | 4,164 |
| 余裕 | 5,836 命令 (58%) |

**結論: プログラムは常に 1 tick 内で完走する。** tick 境界によるコピー中断は発生しない。

### コピーの忠実性

コピーループの構造:
```
LW  r1, r6, 0        ; r1 = self.memory[r6]
OUT r2(=PMEM_AUTOVAL), r1   ; target.memory[addr++] = r1
ADDI r6, r6, 1       ; r6++
BLTL r6, r5(=1024), copy_loop
```

- 自分のメモリ全 1024 ワードを逐語的に読み取り、対象に書き込む
- ノイズ・ランダム性・エラーの注入は一切ない
- I/O の書き込みは `pendingWrites` に蓄積され、tick 内で一括適用される

**結論: コピーは常に完全かつ正確。変異メカニズムは現在存在しない。**

## b. 実験的観察（確認すべき内容）

### 予測

上記の静的分析から、以下が予測される:

1. **メモリは多様化しない**: すべてのコピーが正確なため、世代を経てもプログラム c は常に同一の programC を持ち、プログラム d は常に同一の programD を持つ
2. **初期状態に含まれないメモリ内容は出現しない**: コピー元が常に正確なコピーであり、ランダムな書き換えが発生する経路がない

### 変異が発生しうる唯一のシナリオ

理論的には、以下の場合にのみ「非正規」なメモリ内容が生じうる:

- **同一 tick 内で複数の Processor が同じ停止 Processor にコピーを試みる場合**: Processor は ID 順に逐次実行されるため、先行する Processor がコピー + 起動を完了すると、後続の Processor の SCAN 時にはすでに running=1 となり、対象としてスキップされる。**したがってこのケースも発生しない。**

### 確認実験の提案

上記予測を検証するため、以下のスクリプトによる実験を提案する:

**実験: 500 tick 実行後のメモリ多様性調査**

1. 20 セットの初期状態で 500 tick 実行
2. 全 Processor のメモリをダンプ
3. 以下を計測:
   - programC と完全一致する Processor の数
   - programD と完全一致する Processor の数
   - どちらとも一致しない Processor の数
   - 一致しない場合、差異のあるアドレスと値

**予測結果: 全 Processor が programC または programD と完全一致する（変異ゼロ）。**

## まとめ

v7 の現在の実装では:
- プログラムは 120 ワード / 1024 ワード (12%) を使用
- コピーは 4164 命令で完了し、tick 上限 10000 に対して十分な余裕がある
- **変異メカニズムが一切存在しない**ため、プログラムの多様性は生まれない
- 自己複製は動作するが、それは同一コピーの増殖であり、進化の前提条件を欠いている
