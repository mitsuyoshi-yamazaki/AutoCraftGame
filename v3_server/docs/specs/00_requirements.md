# v3_server 要件

## 概要

v3アプリケーションのゲームシミュレーションがサーバー上で常時実行されており、
ユーザーはWebクライアントからリアルタイムにその状況を確認できるシステム。

## 構成要素

1. **バックエンドサーバー** — v3シミュレーションを常時実行 (TypeScript / Node.js)
2. **インフラ** — AWS EC2上にデプロイ（直接実行）
3. **Webクライアント** — React + pixi.js（読み取り専用）
4. **REST API** — ゲーム状態の取得
5. **リアルタイム通信** — 状態変化のプッシュ配信

## 確定事項

### バックエンド言語・技術スタック

- **サーバー**: TypeScript / Node.js
  - v3以降のゲーム処理をサーバーサイドに移しやすい利点を優先
  - アルゴリズム修正後の速度差（対Rust約2倍）は許容範囲
  - ただしv3のimmutableパターンはmutable化して最適化する
- **クライアント**: React + pixi.js (Canvas描画)

### サーバー側シミュレーション

- 同一サーバー上で複数ワールドが同時実行されうる
- ワールド間でGameParamsが異なることがありうる
- シミュレーション速度はサーバー側で固定（クライアントから変更不可）
- 目標: 10 ticks/sec以上（高速であるほど望ましい）

### ワールド管理

- ワールドの新規作成・終了は開発者がEC2上でCLIコマンドを実行して行う
- ワールドの状態は永続化される
  - チェックポイント: 定期的（半日おきなど）に自動保存
  - 計画されたサーバーシャットダウン時に保存

### クライアント

- 初期バージョンではクライアントからサーバーへの変更操作は一切なし（読み取り専用）
  - 将来バージョンで操作機能を追加する想定
- ゲーム世界のオブジェクトの詳細を閲覧可能
- 複数ユーザーが同時に同じワールドを閲覧可能（5人以下を想定）
- Zoom/Pan/選択などの閲覧状態はユーザーごとに独立

### クライアント機能（既存GUIからの対応）

| 機能 | 対応 | 備考 |
|------|------|------|
| ワールド描画（Canvas）+ Zoom/Pan | 対応 | pixi.js |
| オブジェクト選択 → 詳細パネル | 対応 | |
| 統計情報 | 対応 | |
| イベントログ | 対応 | |
| Play/Pause | 除外 | サーバー側固定 |
| Step | 除外 | |
| 速度変更 | 除外 | |
| Save/Load | 除外 | サーバー側で永続化 |
| Reset | 除外 | 開発者が手動管理 |

### インフラ

- デプロイ先: AWS EC2
- 実行形態: 直接バイナリ（Node.js）実行
- 最初からEC2で実行する（ローカル開発環境は別途）

### MVP (Minimum Viable Product)

統計・イベントログ・複数ワールド対応を含む全機能:
- サーバーで複数ワールドのtickが回る
- ブラウザでワールドを選択し、キャラクターが動いて見える
- オブジェクト選択・詳細表示
- 統計情報表示
- イベントログ表示
- 複数ワールド切り替え
