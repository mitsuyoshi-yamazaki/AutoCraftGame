# バックエンド言語選定

## 評価前提

- 実装者はClaude Code (Opus)
- v3シミュレーションロジック約3,200行を移植対象とする
- サーバーはEC2上で24/7稼働、複数ワールド同時実行

## v3 TypeScript実装のボトルネック分析

v3の現行実装はimmutableデータ操作パターンにより、以下のアルゴリズム的非効率がある:

| ボトルネック | 計算量 | 原因 |
|-------------|--------|------|
| 物理積分ループ | O(C²) | updateCharacter()がループ内でcharacters配列全体をmap |
| ノード再生成 | O(W×H)² | clearMooreResource()がgroundGrid全体をmap（ループ内） |
| 残骸吸収 | O(R×W×H) | 各残骸ごとにgroundGrid全体をコピー |

- C: キャラクター数、W×H: グリッドセル数(3,600)、R: 残骸数
- 毎tick約500KB-2MBのヒープ割り当て（GC負荷）

### 改善余地の分離

1. **アルゴリズム修正**（言語非依存）: O(C²)→O(C)、O(W×H)²→O(W×H)に修正可能。mutableデータ構造を使えばTSでも実現可能。推定効果: **2-4倍高速化**
2. **言語レベル最適化**（Rust/Go固有）: GC排除、メモリレイアウト最適化、SIMD。推定効果: **追加で1.5-2倍**

## 言語別評価

### TypeScript (Node.js)

| 項目 | 評価 |
|------|------|
| 実装コスト | 最小（v3コードほぼ流用、mutable化の改修のみ） |
| 実行速度 | アルゴリズム修正後、ベースラインの2-4倍 |
| メモリ効率 | GCあり。ヒープ負荷は改善可能だが排除はできない |
| 並行処理 | Worker Threadsで複数ワールド対応可。ただしオーバーヘッドあり |
| 経済性(EC2) | 中。同性能ならRustより大きいインスタンスが必要 |

### Rust

| 項目 | 評価 |
|------|------|
| 実装コスト | 高（3,200行の全面書き換え。ただし仕様・参照実装あり） |
| 実行速度 | ベースラインの4-8倍。最も高速 |
| メモリ効率 | GCなし。予測可能なメモリ使用量 |
| 並行処理 | tokio + 各ワールドを独立タスクで実行。効率的 |
| 経済性(EC2) | 最良。小さいインスタンスで多くのワールドを処理可能 |

### Go

| 項目 | 評価 |
|------|------|
| 実装コスト | 中（Rustより書きやすいが、TSほど近くない） |
| 実行速度 | ベースラインの3-6倍 |
| メモリ効率 | GCあり（ただしTS比で大幅に軽量） |
| 並行処理 | goroutineで自然に複数ワールド対応 |
| 経済性(EC2) | 良。Rustに次ぐ |

## 推定コスト比較（EC2月額の目安）

仮定: 5 ticks/sec × 10ワールド = 50 ticks/sec

| 言語 | 1tickあたり所要時間(推定) | CPU使用率 | 必要インスタンス |
|------|--------------------------|----------|----------------|
| TS (修正後) | 5-10ms | 25-50% | t3.medium〜large |
| Go | 2-4ms | 10-20% | t3.small〜medium |
| Rust | 1-2ms | 5-10% | t3.micro〜small |

月額差: Rust vs TS で $10-30/月程度（10ワールド規模）。規模拡大で差は広がる。

## 結論

**Rustを推奨する。**

理由:
1. 24/7稼働サーバーではCPU効率が直接コストに影響する
2. 複数ワールド同時実行でリソース効率の差が倍加する
3. 参照実装（v3 TS）と仕様書が存在するため、移植の不確実性は低い
4. Claude Code (Opus) はRustの実装能力を持っており、開発速度の差は限定的
5. GCなしにより、tick間隔の安定性が向上する（リアルタイム配信に有利）
6. WebサーバーもRust (axum等) で統一でき、単一バイナリでデプロイ可能

ただし、アルゴリズム修正のみでTS据え置きとする選択肢も合理的である。
速度差が「倍以下」かどうかの判定:
- アルゴリズム修正後のTS vs Rust = **約2倍の差**（1.5-2.5倍の範囲）
- これは「倍以下」の境界線上にある
- ワールド数が増えるほど差は実質的に拡大する（絶対値として）

**判断はユーザーに委ねる。**
