# シミュレーション結果レポート

## 実行パラメータ

| パラメータ | 値 |
|-----------|-----|
| ティック数 | 500 |
| マップサイズ | 20x20 |
| 初期Program | `programs/self-replicator.json` |

### 再現コマンド

```bash
npm run sim -- --ticks 500 --program programs/self-replicator.json --map-size 20x20 --output events
```

## 初期状態

### マップ

- 20x20 グリッド
- Ore鉱床: 左半分（x: 0, 3, 6, 9）に3タイル間隔で配置
- Crystal鉱床: 右半分（x: 10, 13, 16, 19）に3タイル間隔で配置
- 資源は毎ティック再生

### 祖先種（char-001）の仕様

**Body構成（最小構成）:**

| コンポーネント | 役割 |
|--------------|------|
| Frame | 構造体 — 耐久値100を提供 |
| Actuator | 移動能力 |
| Sensor | 知覚能力 |
| Processor | 演算（Program実行） |
| Harvester | 資源採取 |
| Assembler | 加工・組立・修理 |
| MemoryCore | Program格納 |

**耐久値:** 100（Frame x1 = 100）

**Program戦略（16ルール）:**

優先度順に以下のフェーズで動作する:

1. **WRITE** — 隣接する非活性キャラクターにProgramをコピー（最優先）
2. **ASSEMBLE** — 全7コンポーネントが揃ったら組み立て
3. **CRAFT** — 加工素材からコンポーネントを製造（7種を順番に）
4. **PROCESS** — 原料を加工素材に変換（Ore→Metal, Crystal→Circuit）
5. **HARVEST** — 資源ノード上にいれば採取（Ore 16個、Crystal 18個まで）
6. **MOVE** — 必要な資源ノードへ向かって移動
7. **NOOP** — 全フェーズ完了時は待機

**必要素材（1体あたり）:**

```
Metal  8個 = Ore  16個
Circuit 9個 = Crystal 18個
合計: Ore x16, Crystal x18
```

### 統計

- **総世代数:** 6（500ティックで5回の自己複製）
- **複製周期:** 約97ティック（安定）
- **寿命:** 99〜100ティック（耐久値100 − 自然劣化1/tick）
- **複製余裕:** 3〜4ティック（寿命 − 複製所要時間）
- **同時生存最大数:** 2体（親が複製直後〜死亡までの数ティック間）

### 行動パターン（各世代共通）

1. **移動フェーズ**（2ティック）: マップ中央から最寄りOre鉱床（9, 9）へ移動
2. **Ore採取・加工フェーズ**（〜48ティック）: Ore採取→Metal加工→コンポーネント製造をインターリーブ実行
3. **Crystal移動・採取フェーズ**（〜40ティック）: Crystal鉱床へ移動→Crystal採取→Circuit加工→残りコンポーネント製造
4. **組立フェーズ**（1ティック）: ASSEMBLE実行 → 非活性キャラクター生成
5. **伝達フェーズ**（1ティック）: WRITE実行 → ProgramをDeep Copy → 娘が活性化

### 検証事項の結果

| # | 検証事項 | 結果 |
|---|---------|------|
| 1 | Programの組立指示でBody構成を自由に決定できるか | **Pass** — ASSEMBLEの`components`引数で任意のBody構成を指定可能 |
| 2 | MemoryCoreのデータコピーでProgramが正しく伝達されるか | **Pass** — 5世代にわたり同一のProgramが正確にコピーされ、各世代が同一の行動パターンを再現 |
| 3 | Program内の組立指示の変更で進化が実現できるか | **Pass** — `evolveProgram()`によりASSEMBLE指示のコンポーネントリストを変更可能（テストで検証済み） |
