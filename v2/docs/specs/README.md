# 次バージョン仕様 — 淘汰圧の導入

## 目的

次バージョンでは、**淘汰圧**の実装に注力する。

淘汰圧と自己複製機能は表裏一体であり、両方を同時に調整するのは困難である。そこで、単体で実装・調整が可能な淘汰圧——すなわち「その世界で行うアクションには必ずコストやトレードオフが伴うこと」——にまず注力する。

## 次バージョンのスコープ

**導入するもの:**

- 資源の有限化（採掘で減少し、再生に時間がかかる）
- 行動コスト（全アクションにエネルギー消費を伴う）
- 物質保存則（資源の総量が一定。死亡時に残骸が残る）
- エネルギーモデル（行動の燃料。decayする）
- 空間的制約（同一タイルの個体数制限、資源分布の不均一化）
- 環境の多様性（地形、資源偏在）

**導入しないもの（以降のバージョンで扱う）:**

- Componentの集合体モデル（個体境界の再定義）
- アセンブラ方式のProgram表現（仮想マシン）
- Programの変異メカニズム
- キャラクター間の攻撃・分解（DISASSEMBLE）
- 通信（SIGNAL）
- 決定論的変異の設計

## 現バージョン（v1）の概要

自己複製可能な自律キャラクターが構築できるかを検証するプロトタイプ。

### 世界モデル

- 20×20の2Dグリッドマップ
- 資源ノード: OreNode 12個（左半分）、CrystalNode 12個（右半分）、グリッド状に均等配置
- tick制: 各キャラクターがtickごとに1アクションを実行

### キャラクター

- 7種のComponent（Frame, Actuator, Sensor, Processor, Harvester, Assembler, MemoryCore）で構成
- JSON形式のルールベースProgram（Condition → Action）を毎tick評価し、最初にマッチしたRuleのActionを実行
- 耐久度: Frameの数 × 200。毎tick -1で自然減衰。0以下で死亡

### クラフトシステム

- 3層の素材階層: 原料（Ore, Crystal）→ 加工素材（Metal, Circuit）→ Component
- 最小構成のキャラクター1体に必要な原料: Ore 16個、Crystal 18個
- 全加工操作は1tickで完了

### 自己複製

- 資源採掘 → 加工 → Component製造 → ASSEMBLE（不活性キャラクター生成）→ WRITE（Program複製）→ ACTIVATE
- WRITEによるProgram完全コピー（クワイン構造）で遺伝が成立

### 淘汰圧に関する現状

| 項目 | 現状 | 問題 |
|------|------|------|
| 資源再生 | 毎tick全ノード完全再生 | 枯渇しないため競争が発生しない |
| 行動コスト | なし（全アクション無料） | 非効率なProgramにペナルティがない |
| 耐久度減衰 | -1/tick（全個体均等） | 行動効率と生存が無関係 |
| 空間制約 | 同一タイルに複数個体可 | 場所の奪い合いが起きない |
| 死亡時 | キャラクター消滅 | 投入された資源が失われ、物質が保存されない |
| 資源分布 | 均等配置 | 空間的な有利不利がなく、戦略の多様化が起きない |

### 検証済みの事項（v1で確認済み）

1. Programの組立指示でBody構成を自由に決定できる
2. MemoryCoreのデータコピーでProgramが正しく伝達される
3. Program内の組立指示の変更で進化（異なる構成の娘）が実現できる
