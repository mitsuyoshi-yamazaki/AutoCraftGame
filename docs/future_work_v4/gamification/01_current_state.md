# 1. v4の現状評価

## 1-1. 達成されていること

### 自律的な自己複製

Mini-Cプログラムにより、キャラクターが以下のサイクルを自律的に完遂する:
- 資源探索 → 採取 → 加工 → 組み立て → プログラム転写 → 起動

このサイクルは500-1000tickを要し、途中でエネルギー補給・修理を挟む必要がある。成功は確約されず、環境状態に依存する。

### 持続的な生死のサイクル

チューニング003により、10000tick以上の継続的な生死サイクルを実現:
- 人口は50-200で振動（爆発も絶滅もしない）
- 世代交代が継続的に発生
- 3種族の共存を達成

### パラメータ進化

Evolver種により、グローバル変数の変異を通じたパラメータ進化を実証:
- 連続変異（小さな差分）
- 親のパラメータ保存・復元パターン
- Mini-C仕様の変更なしで実現

### 物理シミュレーション

連続2D空間、力学ベースの移動、衝突応答、摩擦が動作。

## 1-2. ゲーム体験として不足していること

### 戦略空間の狭さ

現在のv4で実装されている6種族（Pioneer, Gatherer, Evolver, Explorer, Scavenger, Replicator）は、Scavengerを除き全て同一の行動パターンを持つ:

```
SENSE → MOVE → HARVEST → PROCESS → CRAFT → ASSEMBLE → WRITE → ACTIVATE
```

種間の差異は閾値パラメータ（rechargeの開始/終了エネルギー、修理の開始/終了耐久値、wander角度）のみ。根本的に異なる戦略を持つ種が存在しない。

**原因**: 資源獲得パスが1つしかない（Ore+Crystal → Metal+Circuit → Components → Child）ため、全ての種が同じパイプラインを実装する必要がある。

### 種間相互作用の欠如

キャラクター間の直接的な相互作用手段がDISASSEMBLE（残骸の分解）のみ。活性キャラクター同士の干渉手段が存在しない:
- 攻撃不可（他キャラクターの耐久値を減らせない）
- 資源授受不可（アイテムの受け渡しができない）
- 通信不可（情報の発信・受信ができない）

**帰結**: 捕食-被食、協力、分業、軍拡競争が発生しない。生態系の複雑さに本質的な上限がある。

### 観察体験の貧弱さ

v4のUIは個体単位の情報表示に限定されている:
- 種族レベルの人口推移グラフがない
- 系統樹（誰が誰を産んだか）の追跡がない
- 進化パラメータの世代間変化が見えない
- 「なぜこの種族は繁栄/衰退したのか」の分析手段がない

プレイヤーが「面白い」と感じるには、個体の行動だけでなく集団の動態を理解する必要がある。

### プレイヤーの関与手段の不在

現在のv4では:
- 祖先種の投入は初期状態でのみ可能（途中投入不可）
- 環境の変更は不可
- 複数プレイヤーの概念がない

プレイヤーは「設定して、実行して、眺める」以上のことができない。

## 1-3. 競争排除則の壁

生態学の**競争排除則**（Gause's Law）は、同一の生態的ニッチを占める2種は長期的に共存できないことを示す。v4では:

- 全種が同一の資源（Ore, Crystal, Energy）を必要とする
- 全種が同一の変換パイプラインを使用する
- 空間的な棲み分けが弱い（Sensor範囲10に対しフィールド120x80）

チューニング003で3種族の共存を達成しているが、これは閾値パラメータの微差による準中立的共存であり、真のニッチ分化ではない。100種のプレイヤー種を投入しても、最終的には数種に収束する構造的限界がある。

## 1-4. 「面白さ」の未達成

ゲームとしての面白さは、プレイヤーの**意思決定**と**フィードバック**のループから生まれる。現状:

| 要素 | 現状 | 問題 |
|------|------|------|
| 意思決定 | 祖先種のプログラム設計のみ | 設計空間が狭く、最適解が見える |
| フィードバック | 個体レベルの状態表示 | 設計の良し悪しを判断する情報が不足 |
| 不確実性 | 初期配置のランダム性のみ | 毎回同じ展開になりやすい |
| 目標 | 明示的な目標なし | 何を目指せばいいかわからない |
| 社会性 | なし | 他プレイヤーとの競争・協力がない |
