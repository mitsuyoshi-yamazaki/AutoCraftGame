# 2. 「面白い体験の提供」に関する課題

プレイヤーが「面白い」と感じ、継続的に遊ぶためには、**意思決定 → 実行 → フィードバック → 次の意思決定**のループが機能する必要がある。このループの各段階に存在する課題を分析する。

## 2-1. 設計フィードバックの欠如

### 問題

プレイヤーが祖先種を設計・投入した後、その設計が良かったのか悪かったのか、どこを改善すべきかを判断する手段が不足している。

現在のUIが提供する情報:
- 個体ごとのエネルギー、耐久値、インベントリ
- 種族ごとの現在の個体数
- 生死イベントログ（直近10件）

足りない情報:
- **人口推移の時系列**: 種族Aは増加傾向か減少傾向か
- **死因の統計**: 餓死が多いのか、老衰が多いのか、修理不足か
- **複製成功率**: 複製を試みた回数のうち、何割が成功しているか
- **資源効率**: 1複製あたりの消費tick数、消費エネルギー量
- **世代間の変化**: Evolverのパラメータがどう変遷したか
- **系統樹**: どの個体がどの個体を産み、どのラインが生き残っているか

### なぜ重要か

「なぜ自分の種族がうまくいかないか」がわからなければ、改善の方向がわからない。試行錯誤がランダムになり、学習ループが回らない。

### 本質

これは**観測手段の問題**であり、ゲーム仕様の変更ではなくUIとデータ収集の問題である。しかし、ゲーム体験に与える影響は極めて大きい。

## 2-2. ドラマの不在

### 問題

現在のシミュレーションは、初期爆発 → 安定振動 という単調な展開になりやすい。プレイヤーの感情を動かす「ドラマ」——劇的な逆転、予想外の展開、手に汗握る攻防——が構造的に発生しにくい。

**単調さの原因**:
1. 環境が静的（資源の分布や生産量が変わらない）
2. 種間相互作用が間接的（資源の奪い合いのみ）
3. 空間的均質性が高い（どこでも同じ戦略が有効）

**ドラマが発生しうる条件**:
- 局所的な資源枯渇 → 「飢饉」からの脱出劇
- 新種の侵入 → 既存種との勢力争い
- 空間的な制約 → 領域の攻防
- 環境変化 → 適応圧の突然の変化

### なぜ重要か

プレイヤーが見続ける動機は「次に何が起こるかわからない」という不確実性である。予測可能なシミュレーションは飽きる。

### 本質

これは**環境の動的性質**と**種間相互作用**の問題であり、03の「多様性」課題と深く結びつく。

## 2-3. プレイヤーの継続的関与

### 問題

現在のv4では、プレイヤーの関与ポイントが「初期設定時の祖先種設計」のみであり、シミュレーション開始後の関与手段がない。

想定するゲーム体験との乖離:
- **想定**: 常時稼働のサーバーに祖先種を追加投入できる
- **現状**: 初期設定のみ、途中投入不可

**関与の不足**:
- シミュレーション途中での新種投入
- パラメータを変えた改良種の再投入
- 環境操作（資源の追加投入等）は意図的に排除してよい

### なぜ重要か

「デザインして、投入して、結果を見て、改良して、再投入する」のイテレーションが高速に回ることが、プレイヤーの学習と楽しさの源泉。一度設定したら見ているだけでは、試行錯誤の密度が低すぎる。

### 注意

環境操作（資源配置の変更、パラメータの変更等）は「システムとしての進化」を阻害するため、プレイヤーに許可すべきではない。プレイヤーが関与できるのは「祖先種の設計と投入」のみとすべきである。

## 2-4. 競争と社会性

### 問題

想定するゲーム体験は**複数プレイヤーの祖先種が同一フィールドで競争する**ことを核としている。しかし現状、この体験を実現する基盤がない。

**不足要素**:
- プレイヤー間の帰属（「この種族は誰がデザインしたか」の追跡）
- 競争の可視化（「あなたの種族 vs 他プレイヤーの種族」の対比）
- ランキングや実績（継続的プレイの動機）
- 種の命名・アイデンティティ

### なぜ重要か

open-endednessの源泉は人間同士の競争である。単にシミュレーションを観察するだけでは、open-endedな入力（多様な祖先種の継続的投入）が得られない。プレイヤーが「他の誰かの種族に勝ちたい」「自分だけの戦略を編み出したい」と思う動機が必要。

### 本質

これはゲームの**ソーシャル構造**の問題であり、シミュレーション仕様そのものとは独立した、アプリケーション層の課題である。

## 2-5. 観察のスケーラビリティ

### 問題

想定する最終形は数万キャラクターが120x80よりはるかに巨大なフィールドで活動する世界である。このスケールでは:

- 全体を一画面で見ると個体が識別不能
- ズームインすると全体の動態が見えない
- イベント（生死等）が大量に発生し追跡不能

**必要な観察手段**:
- マクロビュー: 種族の空間分布をヒートマップで表示
- メソビュー: 局所的な群れ・集団の行動を追跡
- ミクロビュー: 個体の詳細状態（現在のUIに近い）
- タイムラインビュー: 種族レベルの人口・パラメータ推移

### 本質

これはUI/UXの課題であり、シミュレーション仕様とは独立している。しかし、フィールドの拡大やキャラクター数の増加に先立って、観察手段のスケーラビリティを設計しておく必要がある。

## 課題の相互関係

```
設計フィードバックの欠如  ←→  ドラマの不在
       ↓                          ↓
 改善が見えない          見続ける動機がない
       ↓                          ↓
       └─────── プレイヤー離脱 ───────┘
                    ↓
           祖先種の投入が止まる
                    ↓
            多様性が失われる
                    ↓
         進化のopen-endednessが失われる
```

「面白い体験」の各課題は独立ではなく、全てが**プレイヤーの継続的関与**を維持するために必要な要素である。
