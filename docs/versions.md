# バージョン別 目的と達成度

- **v1**: 自律キャラクターの自己複製が実現可能か検証する
  - Quine機構による自己複製に成功。ただし変異・淘汰圧がなく進化は不可能
- **v2**: 淘汰圧（有限資源・エネルギーコスト・代謝）を導入する
  - 4種族の共存を確認。Scavenger優位やパラメータ感度の高さが課題として残った
- **v3**: 離散グリッドを連続2D空間に置き換え、資源循環を導入する
  - 物理モデルと資源再生を実装。多種族共存にはデフォルト比+80%のエネルギー供給が必要だった
- **v4**: ルールベースプログラムを16ビットVM（Turing完全）に置き換え、進化の基盤を作る
  - 自己複製・多種族共存を達成。プログラム破損で即死する問題が判明し、適応進化の証拠は得られなかった
- **v5**: プログラム破損耐性（CHECKPOINT・リフレックス・アポトーシス・有性生殖）を実装する
  - 堅牢性の基盤を確立。有性生殖はキメラ子の機能不全により効果不十分だった
- **v6**: VM不要の制御プリミティブ（条件→アクション）のみで自己複製できるか検証する
  - AND/OR/NOT複合条件の導入後に自己複製を達成。意思決定の表現力が計算能力より重要と判明した
- **v7**: 「キャラクター」抽象を排除し、Assembler+Processorのみの世界で自己複製を実現する
  - 自己複製は成功したが、コピーが完全で変異メカニズムが一切存在しないことが判明した
- **v8**: コンポーネント間の接続（GroupObject剛体モデル）を導入し、ハイジャッカーで生態的ダイナミクスを検証する
  - 自己複製とハイジャッカー伝播を達成。自己書き換え不能のため真の進化的変異は生じなかった

## v1 — 自己複製の検証

### 目的

自律的に動作するキャラクターが自己複製できることを検証するプロトタイプ。
ゲーム仕様に欠陥がないか、要件を満たせるかを確認する。

検証基準は3つ:
1. プログラムの組立命令でBody構成を自由に決定できること
2. MemoryCoreデータコピーでプログラムが正しく伝達されること
3. プログラムの組立命令変更で異なる構成の子孫を生成できること（進化可能性）

### 達成度

**基盤検証は成功。進化の前提条件は未達成。**

- 達成: Quine機構による自己複製の実装・動作確認。全3検証基準をコード上で実現
- 達成: ルールベースプログラムによる自律行動
- 達成: CLI実行可能なシミュレーション基盤
- 未達成: 変異機構なし（`evolveProgram()`はテスト専用で実行時に動作しない）
- 未達成: 淘汰圧なし（資源が毎tick完全再生、行動コストなし）
- 未達成: プログラム表現がJSON形式で変異に脆弱（1バイト変更で構文破壊）

future_work_v1にて、ダーウィン的進化の3要件（変異・選択・遺伝）のうち遺伝のみ部分達成、変異・選択は未達成と総括。アセンブラ形式への移行、有限資源、行動コスト導入を提案。

## v2 — 淘汰圧の導入

### 目的

v1で欠如していた淘汰圧を導入し、戦略の違いが生存に影響する世界を実現する。
自己複製と淘汰圧は同時調整が困難なため、まず淘汰圧の導入に集中する。

導入した仕組み:
- 資源の有限化（採取で枯渇、再生なし）
- 全行動にエネルギーコスト
- コンポーネント数・所持品に応じた基礎代謝
- 死亡時に残骸化（物質保存）
- タイル占有制約（空間競争）

### 達成度

**淘汰圧の導入に成功。複数種族の共存も確認。**

- 達成: 資源有限化・エネルギーコスト・代謝モデルの実装
- 達成: 4種族（Replicator, Scavenger, Explorer, Survivor）の共存（5シード中3シードで4種共存、10,000tick）
- 達成: 生態学的ダイナミクス（Scavenger-Harvester間の負のフィードバックループ、Survivorの遺伝的リザーバ機能）
- 課題: Scavenger優位（残骸→分解→再構築ループが効率的すぎる）
- 課題: 初期配置のシード依存性が高い（40%のシードで早期絶滅発生）
- 課題: エネルギーがボトルネックで資源はほとんど消費されない（24→17-18ノード/10,000tick）
- 課題: パラメータ感度が高い（FRAME_DURABILITY 200→400で結果が劇的に変化）

## v3 — 連続空間物理の導入

### 目的

v2の離散グリッドを連続2D空間に置き換え、物理ベースの移動（力・速度・加速度）を導入する。
加えて、資源循環システム（残骸吸収・ノード再生）、セーブ/ロード、パラメータ外部化を実現する。

### 達成度

**連続空間物理と資源循環の実装に成功。長期的な多種族共存はチューニング依存。**

- 達成: 連続座標・力ベース移動・摩擦・衝突（バネ反発）・壁境界
- 達成: 360度方向指定のMOVE、距離ベースのアクション判定
- 達成: レジスタシステム（状態機械による高度な行動制御）
- 達成: 資源循環（残骸→GroundGrid吸収→ノード再生、DISASSEMBLE流出）
- 達成: セーブ/ロード・パラメータ外部化（v3.11）
- 達成: 加齢代謝（v3.15、長寿個体の維持コスト増）
- 達成: 4種族以上の共存（energyProductionRate=135, 8シード中8シードで達成）
- 課題: デフォルトパラメータ（eProd=75）では2種族しか安定しない。4種族共存にはeProd=135（+80%）が必要
- 課題: Opportunist（10コンポーネント）は代謝コストが高く、高エネルギー環境でのみ生存可能
- 課題: 加齢代謝導入で4種族共存率が100%→25%に低下（Scavengerの長寿が不利に）
- 課題: 初期配置のシード依存性（一部シードで特定種族が早期絶滅）

12回のチューニング実験（001-012）を通じて、単種族ベースライン→多種族競争→大ワールド→状態機械→バリアント競争→10k安定→資源再生→再生チューニング→新種族→4種族共存→加齢と段階的に検証。

## v4 — VMベースプログラムと進化の基盤

### 目的

v3のルールベースプログラムを16ビットVM（Turing完全）に置き換え、プログラムの変更・コピー・変異を可能にする。
進化アルゴリズムをシステムが提供せず、VM実行の結果として進化が創発することを目指す。

主な設計変更:
- 16ビットVon Neumann統合メモリ（プログラム=データ、自己書き換え可能）
- WRITEアクション: ブロック単位のメモリコピー（src/dst/length指定）
- Mini-Cコンパイラ + アセンブラのツールチェーン
- ローカルID系（プログラムがシステムIDに直接アクセスしない）

### 達成度

**自己複製・多種族共存を達成。進化の創発は部分的。**

- 達成: 自己複製（全シードで成長→飽和→加齢の3フェーズを確認、95births/10,000tick）
- 達成: 2種族共存（Pioneer/Survivor、5シード全てで14,849-15,000tick安定、393-465births）
- 達成: 4種族のライフサイクルバランス（Pioneer/Survivor/Evolver/Explorer、連続的な誕生と死亡）
- 達成: Evolverによるパラメータ変異の動作確認（遺伝的ドリフト観測可能）
- 達成: GUIの実装（v3 UIの移行）
- 未解決: コンパイラ効率問題（関数呼び出しに30-50命令、if-else 7分岐で数百命令）
- 未解決: プログラム堅牢性（PCが不正位置に移動すると回復不能、2ワード命令のアライメント崩壊が連鎖）
- 未達成: 適応的進化の証拠なし（戦略空間が狭く、自然選択圧が不十分）
- 未達成: ゲーム体験（シミュレータとしては動作するがゲームとしては未成立）

future_work_v4にて、ゲーム化に向けたマイルストーン（攻撃、生態的ニッチ、観察UI、マルチプレイヤー等）を提案。

## v5 — プログラム堅牢性

### 目的

v4で判明した「プログラム破損で即死」問題を解決し、進化シミュレータとしての妥当性を確保する。
個体レベルの堅牢性ではなく、集団レベルの堅牢性（破損を許容し、種として再生・選択・遺伝で存続）を目指す。

マイルストーン:
- M1: CHECKPOINT（PC暴走からの回復）
- M2: リフレックス（自動充電・自動修理）
- M3: アポトーシス（機能不全個体の除去）
- M4: エンコーディング冗長性（中立変異の基盤）— 延期
- M5: 有性生殖（cross_write、2親のメモリ混合）

### 達成度

**堅牢性の基盤は達成。有性生殖は実装したが効果不十分。中立変異は延期。**

- 達成: M1 CHECKPOINT（1-3ワード破損で完全回復、5ワード以上で約200tick生存）
- 達成: M2 リフレックス（NOP onlyプログラム+隣接EnergyNodeで1000tick生存、健全個体での誤発火0%）
- 達成: M3 アポトーシス（500tickアイドル/300tick無限ループで死亡、健全個体での誤発火0%）
- 達成: M5 cross_write実装（ブロック交互コピー、ユニットテスト通過）
- 課題: M5の実効性不足（有性生殖の繁殖率が無性の1/4、ブロック境界が関数構造を破壊してキメラ子が機能不全）
- 延期: M4 エンコーディング冗長性（全プログラム再アセンブル必要、効果が間接的で即時観測不能）
- 課題: 長期テストで3種族中2種族のみ生存（SexEvolver絶滅）、1,482births/10,000tick

future_work_v5にて、プリミティブ制御層（Processor不要のキャラクター構築）を提案。v6の方向性を示唆。

## v6 — プリミティブ制御層の検証

### 目的

VM/Processorを使わず、制御プリミティブ（条件→アクションのルールリスト）のみで自己複製が達成できるかを検証する。
v5のfuture_workで提案されたプリミティブ制御層の概念実証。

制約:
- 1tick = 1アクション（VMは複数同時実行可能）
- ルールは先頭から順に評価し、最初にマッチしたルールのアクションを実行
- VMベースキャラクターとの共存が可能な設計

### 達成度

**AND条件の追加により自己複製を達成。条件の表現力が鍵。**

- 未達成→達成: 単純条件のみ（AND/OR/NOTなし）では自己複製不可能。資源の過剰採取や状態遷移の表現不能が原因
- 達成: AND/OR/NOT複合条件の追加後、自己複製に成功（tick 94で初回ASSEMBLE）
- 達成: L4（安定的な個体数増加: 10→201ピーク→134安定）およびL5（種の持続）
- 達成: テンプレート自己参照による世代継承
- 達成: パラメータ変異（ASSEMBLE時にビットフリップ、±3、確率0.02/ワード）
- 課題: 構造変異なし（ルールの追加・削除・並べ替えは不可、数値パラメータのみ変化）
- 課題: 1tick/1アクションの制約でVMの約2倍の時間が必要
- 課題: 明示的な状態変数がなく、`tick_mod`で代替

重要な知見: **計算能力（VM）よりも意思決定の表現力（AND条件）が自己複製の成否を決定する。**

## v7 — WorldObjectモデルとコンポーネント分離

### 目的

v6のルールリスト方式から脱却し、最小単機能Processorを制御プリミティブとして使う方式で自己複製を実現する。
「キャラクター」という抽象を排除し、世界にはAssembler・Processor・素材・エネルギーのみが存在するモデルを構築する。

設計方針:
- 統一WorldObjectモデル（全エンティティが同一の型）
- ランダム移動（制御なし）、衝突なし
- 近接範囲内のオブジェクト間で相互作用
- Assemblerが製造、Processorが制御、両者の組み合わせで自己複製

### 達成度

**自己複製は達成。変異メカニズムは完全に欠如。**

- 達成: Assembler+Processorペアによる自己複製（500tick: 40→56-57コンポーネント、多世代確認）
- 達成: キャラクター抽象なしの統一WorldObjectモデル
- 達成: ランダム移動+近接ベースの相互作用モデル
- 達成: PC相対分岐の導入（BEQL/BNEL/BLTL/BGEL、JMP）でプログラムの位置独立性を確保
- 達成: LABEL/JMPL/LWL/SWL命令の追加
- 未達成: 変異メカニズムが一切存在しない（全コピーがバイト単位で完全一致）
- 未達成: メモリアドレスの多様性（レプリケータがPMEM_ADDR=0をハードコード）
- 課題: IoState永続化により、tick境界でのI/Oシーケンス中断が発生せず、ドリフトアウトによる変異も極めて低確率

5回の変異実験（proximityRange、密度、instructionsPerTickを変化）を実施し、1件のみ部分コピー（117/120ワード）を確認。ドリフトアウト単独では変異源として不十分と結論。

## v8 — 接続と剛体モデル

### 目的

v7に接続（Connection）メカニズムを導入し、コンポーネント間のグループ構造（GroupObject、剛体モデル）を実現する。
Assembler-Processorペアの協調的自己複製と、ハイジャッカー（寄生プログラム）の導入による生態的ダイナミクスを検証する。

設計変更:
- GroupObject抽象（接続されたコンポーネント群が剛体として移動）
- 数値IDによるオブジェクト識別
- 領域分離されたopmem（操作用メモリ）
- ローカルID変換（0x1005）

### 達成度

**自己複製とハイジャッカー伝播を達成。真の進化的変異は未達成。**

- 達成: 接続ベースのGroupObjectモデル（剛体移動）
- 達成: 自己複製プロトコル（v2プログラム: 20→37グループ/1,000tick、HALT 1個追加で60%改善）
- 達成: ハイジャッカーの導入と伝播（単体で人口の50%を乗っ取り可能、97命令で184命令のレプリケータを凌駕）
- 達成: 決定論的再現性（同一シードで差異<3%）
- 課題: fast-ipt（10,000）では変異ゼロ（メモリコピーが1tick内で完了し原子的書き込み）
- 課題: slow-ipt（100）で3件の変異を確認したが、全て既存コードの組み換えのみ（新規命令は生成されない）
- 未達成: 自己書き換え能力の欠如（プログラムはI/O経由で外部のみ書き込み可能、自身のメモリには書き込めない）
- 未達成: 修理・劣化メカニズム（設計案A-Eを検討したが未実装）
- 課題: ハイジャッカー乗っ取り後は「生きているが不毛」な状態（Assemblerが停止し資源未使用）
- 課題: プログラム多様性が2種類に収束（クリーンハイジャッカーとv2末尾付きハイジャッカー、機能的には同一）

future_work_v8にて、修理コスト>再生産コストの経済性とProcessor劣化モデル（メモリ破損、エントロピー蓄積等）を提案。特にメモリ破損（案C）+構造的不可逆性（案E）の組み合わせを推奨。

## v9 — ダイナミックな生態系（クラフトツリー再設計・耐久度・捕食）

### 目的

「進化手法をシステムが提供せず、進化そのものをプレイヤーがプログラム可能な一貫した世界」を実現する。
v8までの「変異メカニズムの限界」を、**コピー忠実度をシステムが規定しない**設計で打破する。

設計変更:
- クラフトツリーの全面再設計（原子7種の保存付きグラフ、35物質・48レシピ、機械検証）
- 8種コンポーネント（Assembler/Disassembler/Processor/MemoryCore/Actuator/Sensor/Harvester/Storage）
- 六角形の辺スロット接続、力ベース物理（v3方式）の復元、シード付きPRNGによる決定論の復元
- 耐久度・残骸・逓増修理（再生産<修理）、自発変化（残骸の自然崩壊）、捕食（Disassembler＋探知＋移動）

### 達成度

**達成 — 本プロジェクトの目的を実証。** 詳細は [v9/docs/CONCLUSION.md](../v9/docs/CONCLUSION.md)。

- 達成: 完全な自己複製（祖先種プログラム約620語、1サイクル約400-500tick、実験01）
- 達成: **目標の3モード（自己複製/自己拡張/自己修復）すべてを別々の種として実証**。
  自己拡張種は自身に部品を接続して4→8部品に成長、自己修復種はREPAIRで延命（実験04）
- 達成: **プログラム自身が実装した複製時変異**（LCG＋1ビット反転、システムは複写I/Oのみ提供）。
  生存する変異体を系統内に観察（実験03）。v7-v8の「コピー忠実性の袋小路」を突破
- 達成: 捕食（探知→追跡→分解、利得＝希少I素材）。単一捕食者がコロニーを7→1個体に削減（実験02）
- 達成: 資源有限性・逓増修理・決定論・個体境界の非定義（R1-R8）
- 達成: 増殖→資源枯渇→老衰死→残骸崩壊→資源還流 の閉じた生態サイクル（原子保存を全実験で維持）
- 知見: 複数コロニーの競争・空間実験（実験05）で、定住種では空間的競争が存在せず、
  局所資源枯渇で必ず絶滅すると判明。空間生態には移動種が前提＝Actuatorの適応価値を定量化
- 範囲外: R9（情報的相互作用の本実装）、移動種の複製、数十万tick規模の開放的進化

v6-v8で直面した「完全なコピー忠実性と自己書き換え不能」の制約を、v9は
「**忠実コピーはデフォルト、変異はプログラムがオプトインで実装する**」という設計で解決した。
進化手法（変異率・粒度・有性生殖・自己書き換え）はすべてプレイヤーのプログラムとして書き分けられる。

| v1 | 自己複製の検証 | 達成 | 変異・淘汰圧なし |
| v2 | 淘汰圧の導入 | 達成 | Scavenger優位、パラメータ感度高 |
| v3 | 連続空間物理 | 達成 | 多種族共存に高エネルギー環境が必要 |
| v4 | VMベース進化基盤 | 概ね達成 | プログラム破損で即死、適応進化の証拠なし |
| v5 | プログラム堅牢性 | 概ね達成 | 有性生殖の効果不足、中立変異延期 |
| v6 | プリミティブ制御層 | 達成 | 構造変異なし、1tick/1アクション制約 |
| v7 | WorldObjectモデル | 部分的 | 変異メカニズム完全欠如 |
| v8 | 接続と剛体 | 部分的 | 自己書き換え不能、プログラム多様性が2種に収束 |
| v9 | ダイナミックな生態系 | **達成** | R9本実装・移動種複製・長期開放進化は今後 |

進化の創発という最終目標に対し、v1-v3で自己複製と淘汰圧の基盤を構築し、v4-v5でVMと堅牢性を整備、
v6-v8で変異メカニズムの根本的限界（完全なコピー忠実性と自己書き換え不能）に直面した。
**v9はこの限界を「コピー忠実度をシステムが規定しない」設計で突破し、進化手法そのものが
プレイヤーのプログラムである世界を実証した。** 残る課題は情報的相互作用の本実装と長期の開放的進化である。
