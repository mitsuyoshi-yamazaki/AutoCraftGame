# 5. 開放性（Open-Endedness）

## 現状の問題

仮に変異と選択が導入されたとしても、現在の仕様では進化が早期に収束（停滞）する可能性が高い。

### 行動空間が固定・有限
- Actionは10種類（MOVE, HARVEST, PROCESS, CRAFT, ASSEMBLE, WRITE, ACTIVATE, SENSE, REPAIR, NOOP）
- Conditionは4種類の基本述語 + 論理演算子
- これらの組み合わせは有限であり、最適解が見つかればそこで進化は止まる

### 新しい「発明」ができない
- 現在のクラフトシステムではレシピが固定されている
- キャラクターが新しい種類のコンポーネントや素材を「発見」する余地がない
- 生物進化における「新しい器官の発明」に相当するものがない

### 複雑性の上限が低い
- Programの長さ/複雑さに上限がある場合、表現可能な戦略に上限がある
- MemoryCoreが1つしかない場合、格納できるデータ量に上限がある

## 不足している仕様

1. **行動空間の拡張可能性**: 進化によって新しい能力が獲得できる仕組み
2. **階層的複雑性**: 単純なものから複雑なものへの段階的進化の経路
3. **共進化の基盤**: 他の個体との相互作用が新しい選択圧を生み続ける仕組み

## 提案

### 5-1. コンポーネントの組み合わせによる能力拡張

現在は各コンポーネントが独立した固定能力を持つ。
同種コンポーネントの複数装備や、組み合わせによる新能力を導入する。

```
例:
- Sensor ×2 → 感知範囲拡大
- Processor ×2 → 1tickで2つのActionを実行可能
- Actuator ×2 → 2マス移動可能
- Harvester ×2 → 1回で2個の資源を採取
```

**効果**:
- Body構成のトレードオフが増える（Sensor増やすと別のコンポーネントに使う資源が減る）
- 「どのコンポーネントをいくつ積むか」が進化の対象になる
- 段階的な能力向上の経路が生まれる

### 5-2. MemoryCoreの拡張とデータ操作

MemoryCoreを単なるProgram格納場所ではなく、汎用的なデータ記憶装置にする。

```
拡張案:
- MemoryCore ×N → 記憶容量がN倍（より長いProgramが格納可能）
- 作業用メモリ領域: Programとは別に、ランタイムで読み書き可能なデータ領域
- READ_MEMORY / WRITE_MEMORY アクション: メモリの任意位置を読み書き
```

**効果**:
- Programが長くなれる → より複雑な戦略が表現可能
- 作業メモリにより「学習」に相当する行動が可能になる（環境情報の記録・利用）
- メモリ操作自体が進化の対象になる

### 5-3. 寄生と共生

アセンブラ方式のProgram表現（01参照）と組み合わせると、Tierraで見られた「寄生」が自然に発生しうる。

```
寄生の例:
- 自身のProgramが短い個体が、隣接する他個体のProcessorの実行結果を利用する
- → 複製コストが低い「寄生虫」が進化する
- → 寄生耐性が進化する → 軍拡競争

共生の例:
- 特定のコンポーネントを持たない個体同士が隣接して互いの機能を補完する
- → 分業による効率化が進化する
```

**注意**: これはProgram表現の設計に強く依存する。ルールベースのProgramでは起きにくく、アセンブラ方式で起きやすい。

### 5-4. マップの拡張性

固定サイズのマップでは個体数に物理的上限がある。

```
案:
- マップサイズを個体数に応じて動的に拡張する
- トーラス構造（端が反対側につながる）で有限だが境界のないマップにする
```

**効果**:
- 個体数の増大に伴い新しい領域が開拓される
- トーラス構造は端に追い詰められる不公平を排除する

## 開放性の本質的な課題

上記は全て「ゲームシステムとして可能性の空間を広げる」提案であり、開放的進化を**保証**するものではない。

真に開放的な進化が起こるかどうかは、以下に依存する:

- **Program表現の計算可能性**: Programがチューリング完全（またはそれに近い）表現力を持つか
- **環境の複雑さ**: 解くべき「問題」が無限に生成されるか
- **個体間相互作用**: 他の個体が環境の一部として機能し、常に新しい適応課題を提供するか

これらは個別の仕様追加では解決できない横断的な設計課題であり、Programの表現形式（01）、淘汰圧（02）、キャラクター間相互作用（03）、環境設計（04）の全てが整合的に設計される必要がある。
