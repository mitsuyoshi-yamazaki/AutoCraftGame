# 2. 淘汰圧（Selection Pressure）

## 現状の問題

現在の仕様では、自然淘汰が機能するための選択圧がほぼ存在しない。

### 資源が無限
- 資源ノードは毎tick完全再生する（game loop step 5）
- 全個体が無制限に資源を獲得でき、資源をめぐる競争が発生しない
- 「効率よく資源を集める」個体と「非効率な」個体の差が生存に影響しない

### 行動にコストがない
- 全Actionが等コスト（1 tick消費のみ）
- 無駄な行動をしてもペナルティがない
- 耐久度の自然減衰（-1/tick）のみが唯一の「コスト」だが、全個体に均等にかかる

### 空間競争がない
- マップが十分広く、資源ノードが均等配置されている
- 個体間でポジションを争う理由がない

## 不足している仕様

1. **資源の有限性**: 資源が消費され、再生に時間がかかる仕組み
2. **行動コスト（代謝モデル）**: 行動に資源やエネルギーを消費する仕組み
3. **環境収容力**: 個体数の上限を生む仕組み

## 提案

### 2-1. 資源の有限化

**現在**: 全ノードが毎tick再生
**提案**: ノードごとに資源量と再生速度を持たせる

```
ResourceNode = {
  type: Ore | Crystal,
  remaining: number,    // 現在の資源量（0で採掘不可）
  maxCapacity: number,  // 最大資源量
  regenRate: number,    // tick当たりの再生量
}
```

- HARVESTで `remaining` が1減少する
- 毎tickで `min(remaining + regenRate, maxCapacity)` に回復
- `regenRate` を低く設定すれば、複数個体が同じノードを使うと枯渇する → 競争が発生

**パラメータの目安**: 1個体の自己複製に必要な資源量（Ore 16, Crystal 18）と、再生速度のバランスで淘汰圧の強さを調整可能。

### 2-2. 代謝モデル（エネルギーコスト）

現在の耐久度は「寿命のカウントダウン」でしかなく、行動の効率性に差をつけない。

**提案**: 行動ごとにエネルギー（耐久度、または別リソース）を消費する。

```
Action別コスト例:
  MOVE:     -1 durability
  HARVEST:  -1 durability
  PROCESS:  -2 durability（加工は負荷が高い）
  CRAFT:    -2 durability
  ASSEMBLE: -3 durability（最も負荷が高い）
  SENSE:    -1 durability
  NOOP:      0（何もしなければ消費しない）
  自然減衰:  -1/tick（現行と同じ）
```

**効果**:
- 無駄な行動をする個体は早く死ぬ → 効率的なProgramが有利
- REPAIR判断のタイミングが生存に直結する戦略的要素になる
- 行動しないこと（NOOP）にも意味が生まれる

**別アプローチ: エネルギーリソースの導入**

耐久度とは別に「エネルギー」リソースを導入する手もある。
- 特定の資源を消費してエネルギーを得る（食事に相当）
- 全行動がエネルギーを消費する
- エネルギー0で行動不能 → 耐久度だけが減り続けて死亡

これは耐久度（=構造的損傷）とエネルギー（=活動資源）を分離し、より豊かなトレードオフを生む。ただし仕様の複雑さも増す。

### 2-3. 空間的制約

**提案**: 以下のいずれかで空間競争を生む。

- **同一タイルの個体数制限**: 1タイルに1個体まで（移動がブロックされる）
  → 資源ノードへのアクセス競争が発生
- **資源ノードの偏在**: 均等配置でなく、クラスタ状に配置する
  → 「良い場所」をめぐる競争が発生

## 淘汰圧のバランス

淘汰圧が強すぎると全滅し、弱すぎると進化が起きない。
パラメータ（資源再生速度、行動コスト、マップサイズ）で調整可能にすべきだが、適切な値は実験で見つける必要がある。

シミュレーションのパラメータをコマンドライン引数または設定ファイルで外部から指定できる設計にしておくことを推奨する。
