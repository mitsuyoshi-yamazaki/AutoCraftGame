# 3. キャラクター間相互作用

## 現状の問題

現在の仕様では、キャラクター間の相互作用がほぼ存在しない。

- **SENSE**: 他キャラクターの位置を検知できるが、それ以上の情報は得られない
- **WRITE/ACTIVATE**: 自分が作った不活性キャラクターに対してのみ作用する
- **直接的な干渉手段がない**: 攻撃、資源の授受、コンポーネントの奪取などが不可能

相互作用がなければ、各個体は孤立して資源を集め複製するだけであり、以下が起こらない:

- 共進化（軍拡競争）
- 協力行動の進化
- 捕食-被食関係
- 生態的ニッチの分化

## 不足している仕様

1. **キャラクター間の物理的干渉手段**
2. **資源やコンポーネントの授受**
3. **他キャラクターの情報取得**

## 提案

### 3-1. 攻撃・分解（ATTACK / DISASSEMBLE）

他キャラクターのコンポーネントを損傷させる、または分解して奪う。

```
ATTACK(target):
  - 対象の耐久度を減少させる
  - 必要コンポーネント: Actuator（物理的接触が必要）
  - 隣接タイルの対象にのみ有効

DISASSEMBLE(target):
  - 対象（不活性または死亡キャラクター）からコンポーネントを取得する
  - 必要コンポーネント: Assembler
  - 既存の「組み立て」の逆操作
```

**効果**:
- 「略奪者」戦略が可能になる（自分で資源を集めるより、他者から奪う方が効率的な場合がある）
- 防衛戦略（逃走、複数Frame装備による高耐久化）の進化圧になる
- 捕食-被食の共進化が起こりうる

**注意**: ATTACKを入れると攻撃特化が支配戦略になるリスクがある。コスト設計（攻撃にも高コスト）やコンポーネント要件で調整が必要。

### 3-2. 資源の授受（GIVE / TAKE）

```
GIVE(target, item, count):
  - 隣接キャラクターに自分のインベントリからアイテムを渡す
  - 対象のインベントリに追加

TAKE(target):  ← 相手の同意が必要か？
```

**効果**:
- 「分業」が進化しうる（採掘特化と加工特化の協力）
- 親子間の資源供給が可能になる
- ただしGIVEだけでは利他行動が進化しにくい。血縁選択（kin selection）が機能するには、血縁度を判別する仕組みが必要

### 3-3. SENSEの拡張

現在のSENSEは位置情報のみ。他キャラクターの状態を知る手段を追加する。

```
SENSEで取得可能な情報の拡張案:
- 対象のコンポーネント構成（Body情報）
- 対象の耐久度
- 対象のインベントリ（一部または全部）
- 対象が活性か不活性か
```

**効果**:
- 「弱っている個体を狙う」「同族を識別する」などの条件分岐が可能になる
- 協力・敵対の判断基盤になる

### 3-4. 通信（SIGNAL）

```
SIGNAL(data):
  - 周囲一定範囲にデータを発信する
  - 受信側はSENSEで取得可能
```

**効果**:
- 間接的な協力の基盤（「ここに資源がある」というシグナル）
- ただしProgram表現が十分に豊かでないとシグナルを解釈できない
- アセンブラ方式のProgram表現と組み合わせると、シグナルのエンコード/デコードも進化の対象になる

## 優先度

最終目標に対する寄与度で考えると:

1. **DISASSEMBLE**（高）: 死亡キャラクターの「リサイクル」は資源循環を生み、生態系の基盤になる
2. **SENSEの拡張**（高）: 相互作用の前提として、他者の情報を得る手段が必要
3. **ATTACK**（中）: 共進化の強力な駆動力だが、バランス調整が難しい
4. **GIVE**（中）: 協力行動の進化に必要だが、利他行動が進化するには他の条件も必要
5. **SIGNAL**（低）: 最も豊かな可能性を持つが、Program表現の改革が先に必要
