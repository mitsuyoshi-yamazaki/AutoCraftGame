# Processor の劣化機構

## 目的

Processor（コンピュータ）に決定論的な性能劣化を導入し、「修理コスト > 再生産コスト」の制約をクラフトレイヤーで実現する。

## 設計制約

1. **決定論的**: 確率的な失敗やランダム要素を使わない
2. **離散的**: コンピュータの故障は「1% 性能低下」のような連続的なものではなく、離散的なイベントとして表現する
3. **クラフト誘導**: 劣化そのものへのプログラム適応（命令セット削減、レジスタ節約、配置回避等）が最適戦略にならず、「劣化する前にクラフトレイヤーで再生産する」が最適戦略になること

## 初期案（劣化単位がプログラム構造に依存するもの）

以下の案は「劣化への適応」が可能であり、その適応圧がクラフトレイヤーの圧力を上回りうるため、設計制約 3 を満たさない。参考として記録する。

### メモリセル固着（アドレス単位の死）

特定のメモリアドレスが固着する（読み出しは固着時の値、書き込みは無視）。累計命令数の閾値ごとに固着アドレスが 1 つ増える。

- 物理的根拠: SRAM/フラッシュの bit stuck
- **問題**: プログラムが固着アドレスを避けて配置を変えることで適応可能。「配置最適化」が主要な淘汰圧になる

### 書き込み摩耗（フラッシュメモリモデル）

各メモリアドレスに書き込み回数カウンタを持ち、上限 W 回に達したアドレスは読み出し専用になる。

- 物理的根拠: フラッシュメモリの書き込み寿命
- **問題**: 書き込みを分散させるプログラム（ウェアレベリング構造）が有利になる。「書き込みパターン最適化」が主要な淘汰圧になる

### レジスタファイルの縮退（レジスタ単位の死）

累計命令数の閾値で r7 → r6 → ... → r1 の順にレジスタが使用不能（読み出し常に 0、書き込み無視）になる。

- 物理的根拠: レジスタファイル故障
- **問題**: 少ないレジスタで動作するプログラムが有利になる。「レジスタ使用削減」が主要な淘汰圧になる

### ワード幅の縮小（精度劣化）

メモリ・レジスタの有効ビット幅が段階的に狭まる (16bit → 15bit → ... → 0bit)。書き込み時に上位ビットがマスクされる。

- 物理的根拠: バス幅劣化
- **問題**: 小さい値のみを使うプログラムが有利になる。「値の範囲最適化」が主要な淘汰圧になる

### 命令デコーダの故障（opcode 単位の死）

累計命令数の閾値で opcode が 1 つずつ NOP 化される。複雑な命令から順に停止。

- 物理的根拠: デコーダ回路故障
- **問題**: 少ない命令種別で構成されたプログラムが有利になる。「命令セット削減」が主要な淘汰圧になる

## クラフト誘導型の案

以下の案は、プログラムの構造変更による適応余地がゼロまたは極めて小さく、唯一の対処が「クラフトレイヤーで新品を生産すること」になるもの。

### 案 A: 累計 tick 寿命（純粋な経過時間型）

**挙動**: Processor は running 状態の累計 tick 数を内部カウンタとして持つ。閾値 T tick に達すると permanently stopped になり、`run_flag` への書き込みも無視される。

```
age = 0 (生成時)
毎 tick (running 中): age++
age >= T: stopped (不可逆)
```

**プログラム適応の余地**: ゼロ。どんなプログラムでも 1 tick あたり 1 ずつ age が進む。HALT しても tick は消費される。プログラムの構造・長さ・効率に一切依存しない。

**クラフトレイヤーへの圧力**: 「T tick 以内に新しい Processor を作り、プログラムをコピーし、起動する」ことがすべて。高速な自己複製プログラムが有利。

**物理的根拠**: MTBF（平均故障間隔）。時間依存の故障は現実のシステムにおいても普遍的。

**考察**: 仕組みが極めて単純。「なぜ時間だけで壊れるのか」の直感はやや弱いが、法則の primitive さは高い（パラメータは T のみ）。

### 案 B: 累計命令寿命（命令予算型）

**挙動**: Processor は生涯で実行可能な命令の総数 N が固定されている。命令が 1 つ実行されるたびカウンタをデクリメント。0 に達したら permanently stopped。

```
budget = N (生成時)
命令実行ごと: budget--
budget == 0: stopped (不可逆)
```

**プログラム適応の余地**: HALT は「命令を消費しない」ため、HALT を多用すれば calendar time としての寿命は延びる。ただし HALT 中はプログラムが一切進行しないため、「有用な仕事」の総量 N は変わらない。

**クラフトレイヤーへの圧力**: 自己複製に必要な最低命令数（CSCAN + opmem 操作 + 1024 ワードコピー + disconnect ≈ 1100〜1200 命令）が固定コスト。N に対するこのコストの比率が「生涯何回複製できるか」を決める。無駄な命令を減らす圧力が生じるが、これは「再生産効率の向上」に直結するため、クラフトレイヤーへの圧力と一致する。

**案 A との差異**: 案 A は「時間が来たら死ぬ」。HALT で待機中も寿命を消費するため、素材待ちのコストがゼロ。案 B は「仕事をした分だけ減る」。待機中は消耗しないが作業中は消耗する。「材料が揃うまで HALT で待つ」コストの有無が異なる。

**物理的根拠**: バッテリー消費。充電不可の一次電池モデル。

### 案 C: I/O ポートの順次停止（外部接続の劣化）

**挙動**: Processor の内部演算（ALU、レジスタ、メモリ）は一切劣化しない。代わりに、外界との接続に使う I/O ポートが、累計使用回数に応じて順次停止する。

```
I/O 総使用回数: ioCount (IN/OUT 実行ごとに +1)

ioCount >= K1: 外部 PMEM (0x2000-0x2FFF) 停止 → プログラムコピー不可
ioCount >= K2: 0x1005 (ID変換) 停止 → ローカルID橋渡し不可
ioCount >= K3: 外部 OPMEM (0x1000-0x1FFF) 停止 → Assembler 操作不可
ioCount >= K4: SCAN/CSCAN 停止 → 周囲の認識不可
ioCount >= K5: 自身 OPMEM (0x0100-0x01FF) 停止 → 完全孤立
```

停止した I/O ポートへの OUT は無視、IN は 0 を返す。

**プログラム適応の余地**: I/O はハードウェアポートであり、別アドレス経由でのアクセスは不可能。I/O 効率を上げて使用回数を節約する余地はあるが、自己複製に必要な最低 I/O 回数（≈ CSCAN 2 回 + opmem 操作 ~20 回 + PMEM コピー 1026 回 ≈ 1050 回）は削減不能。

**クラフトレイヤーへの圧力**: 最初に死ぬのが PMEM（プログラムコピー能力）、次に ID 変換、次に Assembler 操作という順序にすれば、**自己複製に不可欠な能力から順に失われる**。「再生産能力が先に消える」という直接的なクラフト圧力が発生する。

**物理的根拠**: I/O コントローラの接点摩耗。内部演算は正常だが世界への働きかけが劣化するモデルは、コンピュータの故障として直感的。

**考察**: 案 A/B/D が「一律に壊れる」のに対し、この案は「クラフトに必要な機能から壊れる」という指向性がある。この指向性がプリミティブかどうかは議論の余地がある。

### 案 D: メモリ全域の決定論的減衰（情報エントロピー型）

**挙動**: Processor の running 累計 tick が K の倍数に達するたび、メモリの全 1024 ワードに対して一律の固定変換が適用される。全ワードの最下位ビットからクリアされていく。

```
age =   0: メモリはそのまま
age =   K: 全 mem[i] = mem[i] & 0xFFFE  (bit 0 クリア)
age =  2K: 全 mem[i] = mem[i] & 0xFFFC  (bit 0-1 クリア)
age =  3K: 全 mem[i] = mem[i] & 0xFFF8  (bit 0-2 クリア)
...
age = 16K: 全 mem[i] = 0 (全ビットクリア → 死)
```

**プログラム適応の余地**: ゼロ。全アドレスに同一変換が適用されるため、「安全な領域に配置する」「特定のアドレスを避ける」戦略は意味をなさない。命令エンコーディングの低位ビットが壊れることで、全てのプログラムが同じ速度で劣化する。

**クラフトレイヤーへの圧力**: メモリが壊れる前に「新品の Processor にコピーすること」が唯一の対処。コピー元の情報が壊れていない段階でコピーを完了する必要がある。

**物理的根拠**: DRAM の電荷リーク。デジタル回路で電荷が自然放電すると、全ビットが 0 に向かって収束する。これはリフレッシュが無い DRAM で実際に起きる現象。

**考察**: 16 段階の離散的劣化。初期段階（bit 0 のみクリア）では命令セットの一部はまだ正常に動作する可能性があり、「部分的に壊れているが何かをしている」状態が一時的に存在しうる。これは変異の源として興味深い。
