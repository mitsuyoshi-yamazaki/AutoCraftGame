# プログラムロバスト性: 目標達成に向けた評価とロードマップ

これまでに [proposals](program_robustness_proposals.md), [bio_inspired](program_robustness_bio_inspired.md), [execution_models](program_robustness_execution_models.md) で14案を検討した。本文書では、これらをプロジェクトの最終目標に照らして評価し、現実的な進路を提示する。

## 最終目標の再確認

[CLAUDE.md](../../../CLAUDE.md) およびこれまでの議論から、最終目標は2軸ある:

### 軸X: プログラム可能性（人間視点）

- 人間が祖先種を自由に構成・プログラムできる
- 必要であれば高度なアルゴリズムも実装できる
- プログラム内容によって、様々な拡張/自己複製/進化手法を取りうる

### 軸Y: 自律進化と生態系（システム視点）

- キャラクターが自律的に行動する
- 拡張・自己複製・進化を続ける
- 多様な生態系が持続する

## 現状とのギャップ分析

各目標について、現状達成度と残るギャップ:

| 軸 | 現状 | ギャップ |
|----|------|---------|
| **X. プログラム可能性** | ✓ Mini-Cで5種族を実装済み | プログラムが脆弱で、書いた通りに動くが、変異は受け入れない |
| **Y1. 自律行動** | ✓ 各キャラクターは自律実行 | 行動の柔軟性が低い（破損で即停止） |
| **Y2. 自己複製** | ✓ 全種族が複製可能 | 複製時のコピー忠実性が高すぎ、変異の余地が小さい |
| **Y3. 進化** | △ Evolverのパラメータ進化のみ | プログラム構造の進化は実質的に不可能（破損=即死） |
| **Y4. 多様な生態系** | ✗ 単一種優占または絶滅 | 種間の動的均衡が成立していない |

**最大のギャップはY3（進化）とY4（生態系）**にある。これらが達成されないのは、現状のVMが「変異を許容しない」性質を持つためである。

## 軸Xと軸Yの本質的な緊張関係

ほとんどの提案は、軸Xと軸Yのどちらかを犠牲にする:

- **軸Xを優先**: 既存のMini-C方式を維持。ただし変異耐性は低い
- **軸Yを優先**: イベント駆動・データフロー・プロダクションシステムなど。ただし手続き的記述力が制限される

**この緊張を解消する提案は希少である**。本文書の核心は「両軸を満たす道筋は存在するか」を判定することにある。

## 14案の目標貢献マップ

各案を「軸Xを保つか」「軸Yを進めるか」で分類する:

| 案 | 軸Xへの影響 | 軸Yへの貢献 | 性質 |
|----|---------|----------|------|
| a. 符号化冗長化 | 中立（透過的） | 中（中立変異） | 追加的 |
| b. 分散制御 | △（プログラム責務縮小） | **大**（失敗局所化） | 置換的 |
| c. イベント駆動 | ×（手続き記述困難） | **大**（PC廃止） | 置換的 |
| d. 反射 | 中立（プログラム外） | 中（最低生存保証） | **追加的** |
| e. 有性生殖 | 中立 | **大**（致死変異遮蔽） | 追加的 |
| f. アポトーシス | 中立 | 中（集団効率） | **追加的** |
| g. 形態学的計算 | △（プログラム責務縮小） | 中 | 置換的 |
| h. 環境外部化 | 中立 | 中 | 追加的 |
| i. マルチスレッド | ○（拡張のみ） | 中（局所化） | 追加的 |
| j. データフロー | ×（記述方式変更） | **大** | 置換的 |
| k. アクターモデル | ○（局所内は同等） | **大**（メモリ分離） | 置換的 |
| l. プロダクションシステム | △（ルール記述） | **大** | 置換的 |
| m. チェックポイント | **○（完全保持）** | **大**（PC回復） | **追加的** |
| n. マルチエントリ | △（tick跨ぎ不可） | 中 | 追加的 |

**「軸Xを犠牲にせず軸Yを進める」案**は次の組み合わせに集約される:

- **m. チェックポイント**: 既存プログラム互換、PC迷走から回復
- **d. 反射**: プログラムの外側で生存保証
- **f. アポトーシス**: 破損個体の自然淘汰
- **a. 符号化冗長化**: 中立変異の獲得
- **e. 有性生殖**: 集団レベルの致死変異遮蔽
- **i. マルチスレッド**: 機能の独立並行実行（オプショナル）

これらは全て**追加的**であり、既存システムに段階的に重ねられる。軸Xを保ったまま軸Yを進める道筋となりうる。

## 段階的マイルストーン案

上記の追加的提案を、実装難易度と効果が出る順序で並べると以下のマイルストーンになる:

### マイルストーン1: PC迷走の克服（案m: チェックポイント）

**実装内容**:
- VMに `CHECKPOINT` 命令（1ワード）と特殊レジスタ `cp` を追加
- tick開始時に `PC ← cp` を実行（cp=0が初期値、未設定時はアドレス0）
- Mini-Cに `checkpoint()` 組み込み関数を追加
- 既存プログラムに `checkpoint()` を散りばめる

**達成できること**:
- 制御フローが破損してもtick跨ぎで必ず回復する
- プログラムの一部が破損しても、他の部分は動作を続けられる
- **自己複製時の変異が「即死」ではなくなる初めての段階**
- write_memoryでコピー時に1ワードでも狂えば即死だった現状から脱却する

**観察可能になること**:
- 子個体の変異が部分的に動作する事例
- 「親と少しだけ違う子」が生まれて成育する個体
- まだ意味的な進化は起きないが、**非致死変異の存在が初めて確認できる**

**未達成のもの**:
- 中立変異の頻度はまだ低い（破損→修復はあっても、破損→別の有意な動作にはならない）
- 集団レベルの動態はまだ単調

### マイルストーン2: 個体の最低限の生存保証（案d: 反射）

**実装内容**:
- VM/I/Oハンドラに条件付き自動アクション機構を追加
- 反射の例:
  - エネルギー閾値以下 + 近傍にエネルギーノード + N tickアクションなし → 自動recharge
  - 耐久度閾値以下 + N tickアクションなし → 自動repair
- 反射は「プログラムが何も指示していない場合」に限り発動
- 反射が消費するエネルギーは通常アクションと同じ

**達成できること**:
- プログラムが完全に破損した個体でも、しばらく生存できる
- 進化が「致死前に変異が定着する時間」を持てる
- 親プログラムが破損していても、子を作って次世代に渡せる可能性が出る

**観察可能になること**:
- 「プログラム壊れているが反射で生きている個体」
- このような個体が複製した場合の子の挙動
- 反射に依存する戦略を持つ進化系統が現れるか

**未達成のもの**:
- 反射の対象範囲を超える複雑な行動（収穫戦略、複製戦略）はまだプログラムに依存
- 多様な生態系の形成にはさらに案が必要

### マイルストーン3: 集団レベルの淘汰（案f: アポトーシス）

**実装内容**:
- VMに「機能不全検出」を追加
- 検出条件: M tick連続で命令上限到達、または K tick間アクション発行ゼロ
- 検出時、キャラクターを強制死亡させる（残骸として残る）
- 残骸のコンポーネントは他個体が再利用可能

**達成できること**:
- 機能不全個体がリソースを浪費し続けない
- 集団内の「平均健全性」が向上する
- 健全な個体の複製が促進される

**観察可能になること**:
- 集団のターンオーバーの加速
- 「壊れた個体は早く死に、健全な個体が増える」という単純な選択圧の効果
- 種としての持続性の向上

**未達成のもの**:
- 種内の遺伝的多様性はまだ限定的（無性生殖のため）

### マイルストーン4: 中立変異の獲得（案a: 符号化冗長化）

**実装内容**:
- 改善案a-方式1（opcodeグルーピング）を採用
- アセンブラを更新し、各命令を複数のbitパターンで表現可能に
- 既存プログラムは新エンコーディングで再アセンブル

**達成できること**:
- 単bit反転の多くが命令を変えない（中立変異の存在）
- 自己複製時の小さなコピーミスが、子に何らかの影響を与えずに済む
- **進化的にゲノム空間の探索が初めて意味を持つ**

**観察可能になること**:
- 親と「同じ動作だが少し違うプログラム」を持つ子
- 中立変異の蓄積による、ある世代での「突然の機能変化」（中立進化）
- 進化的時間スケールでの種内多様性

**未達成のもの**:
- 集団レベルの多様性管理はまだ無性生殖に依存

### マイルストーン5: 集団遺伝学的動態（案e: 有性生殖）

**実装内容**:
- 物理的近接時（または明示的アクション）に2親のメモリを混合する機構
- 領域ごとに親A・親Bの値を交互に採用（交差点はランダム）
- write_memoryの2親バージョン

**達成できること**:
- 1親の致死変異がもう1親により遮蔽される
- 集団内の遺伝的多様性が維持される
- 異なる進化系統の遺伝子が組み合わさる

**観察可能になること**:
- 「親A型の特徴」と「親B型の特徴」を併せ持つ子
- 配偶者選択の進化（特定の相手を選ぶ戦略）
- 種内の系統分岐と再結合

**未達成のもの**:
- 真の意味での「種分化」と「ニッチ分化」はまだ限定的

### マイルストーン6: 機能の独立並行実行（案i: マルチスレッド、オプション）

**実装内容**:
- VMにスレッド機構を追加
- Mini-Cに `spawn_thread(addr)` を追加
- 各スレッドは独立PC・レジスタ・スタック、メモリは共有

**達成できること**:
- 機能ごとの独立実行（収穫スレッド、充電スレッド、複製スレッド）
- 1機能の破損が他機能を止めない
- プログラムの並列性がプログラマブルになる

**観察可能になること**:
- 「収穫はできないが複製はできる」のような部分機能個体
- スレッド単位の進化（特定スレッドだけ変異）

## ロードマップ全体像

```
[現状]
  ↓
M1: チェックポイント (案m)
  ↓ — PC迷走克服、非致死変異の出現
  ↓
M2: 反射 (案d)
  ↓ — 完全破損個体の生存延長
  ↓
M3: アポトーシス (案f)
  ↓ — 集団のターンオーバー
  ↓
M4: 符号化冗長化 (案a)
  ↓ — 中立変異、ゲノム空間探索
  ↓
M5: 有性生殖 (案e)
  ↓ — 集団遺伝学的動態
  ↓
M6: マルチスレッド (案i, オプション)
  ↓
[第一段階の完成: 軸Xを保ったまま、進化と生態系のy初期形態が成立]
```

各マイルストーンは独立して評価可能で、必要に応じて次に進める。途中で停止しても、それまでの改善は累積する。

## 第一段階で達成できると期待されること

M1〜M5を順次達成した時点で、以下が**観察可能**になることを期待する:

1. **非致死変異の存在**: 親と少し異なるプログラムの子が生まれ、成育する
2. **中立進化の蓄積**: 表現型を変えない変異がゲノムに蓄積する
3. **稀な突然変異による機能変化**: 蓄積した中立変異が、組み合わせで初めて新機能を生む例
4. **個体破損からの種の存続**: 個体は壊れるが、種としては進化を続ける
5. **集団動態**: 健全個体と破損個体の動的均衡、世代交代の自然な流れ

これらは「進化シミュレーション」として最低限必要な現象であり、現状では1つも観察できていない。M1〜M5の完了で**最初の現象観察**が可能になる。

## 第一段階で達成できないこと

以下は依然として未解決:

- **真の種分化**: 1つの祖先種から複数の異なる種が分かれる現象
- **ニッチ分化**: 種間で資源使用パターンが分かれる現象
- **共進化**: 種間の相互影響による進化
- **複雑な行動戦略の進化**: 単純なパラメータ変化を超えた、戦略構造そのものの進化

これらの達成には、第二段階として案b（分散制御）、案k（アクターモデル）、案g（形態学的計算）、案h（環境外部化）などの根本的な再設計が必要になる。第一段階で蓄積した知見が、第二段階の設計指針となる。

## 推奨される次のアクション

### 短期: M1（チェックポイント）の試験実装

理由:
- 実装コストが極小（VMに1命令、特殊レジスタ1個、tick開始時の1行）
- 既存プログラムを変更せずに動作する（後方互換）
- 単独で「非致死変異」という測定可能な変化をもたらす
- 効果が出なければ次の案に進む判断材料になる

具体的タスク:
1. VM仕様書に `CHECKPOINT` 命令と `cp` レジスタを追記
2. vm.tsの実装、テスト追加
3. assembler.tsとMini-Cコンパイラに `checkpoint()` 組み込み関数を追加
4. 既存プログラム1種（Pioneerなど）に `checkpoint()` を配置
5. 意図的に破損させた状態でのGUI/CLI動作確認

### 中期: M2〜M5の段階的導入

各マイルストーンの効果を観察しながら次に進む。各マイルストーン後、進化シミュレーションを長時間実行し、現象観察を行う。

### 長期: 第二段階の設計検討

M1〜M5の知見を踏まえ、案b / k / g / h を組み合わせたv5のアーキテクチャを設計する。本文書とは別の議論として立ち上げる。

## まとめ

軸X（プログラム可能性）を保ったまま軸Y（進化と生態系）を進められる案は、**追加的**な6案（m, d, f, a, e, i）の組み合わせである。

- M1〜M5は段階的に実装可能で、各段階で観察可能なマイルストーンを持つ
- 第一段階の完了で、現状で観察できない進化現象の初期形態が成立する見込み
- 第二段階（v5）への根本的な再設計は、第一段階の知見を踏まえて行う
- **最も低コストで効果が大きい次の一歩は M1（チェックポイント）の試験実装**である
