# プログラム破損ロバスト性: 生物学的着想による追加提案

Issue [005](../issues/005_program_robustness.md) の課題に対し、[改善案a, b](program_robustness_proposals.md) で扱わなかった、生物学的メカニズムから着想を得た追加提案を整理する。

これらは既存のゲーム仕様から大きく外れるが、本プロジェクトの最終目標（自律的活動の結果としての進化の創発）に貢献する方向性を持つ。

## 観点: 生物が変異ロバスト性を実現する方法

生物は破壊的変異を許容しながらも種として進化を続けている。その実現には複数の機構が組み合わさっている:

| 機構 | 生物での実現 | ロバスト性への貢献 |
|------|------------|----------------|
| **遺伝コードの冗長性** | 4塩基×3=64コドン → 20アミノ酸（ほとんどが同義置換可能） | 同義変異の存在 |
| **遺伝子の分節化** | 1ゲノムに数千の独立遺伝子 | 1遺伝子破損が他に影響しない |
| **転写の事象駆動性** | 転写因子が結合 → 遺伝子発現開始 | 順序的プログラムでなく条件→反応のルール集合 |
| **読み枠とストップコドン** | 開始コドンATGから始まり、3塩基単位で読み、ストップコドンで終端 | 翻訳の同期点とgraceful termination |
| **タンパク質の折りたたみ柔軟性** | 多少のアミノ酸置換でも構造を維持 | 表現型レベルの中立性 |
| **熱ショックタンパク質** | 誤った折りたたみを補正・隠蔽 | 変異の表現型を一時的に緩衝 |
| **有性生殖と組換え** | 2親のゲノムを混合 | 劣性致死変異の遮蔽 |
| **アポトーシス** | 異常細胞の自発的死 | 個体内の異常細胞の除去 |
| **反射神経・本能** | 大脳によらない原始的行動 | 上位制御が壊れても基本的生存可能 |
| **個体死と種レベル選択** | 個体は死ぬが種は生き残る | 個体ロバスト性が低くても種は進化 |
| **形態学的計算** | 物理的構造そのものが計算を担う | 神経系破損でも歩行可能 |
| **環境への外部化（stigmergy）** | フェロモン・痕跡で集団を協調 | 個体記憶でなく環境記憶 |

これらのうち、本プロジェクトに導入可能な提案を以下にまとめる。

## 改善案c: イベント駆動型プログラミングモデル（生物の遺伝子発現に対応）

### アイデア

PCを中心とした逐次実行モデルを廃止し、代わりに**「条件 → 行動」のルール集合**としてプログラムを表現する。

- メモリには多数の「ルール」が格納される。各ルールは独立した小さな単位
- 各tickで、VMはすべてのルールを評価し、条件を満たすルールの行動部を実行する
- ルール間に明示的な順序はない（または優先度のみ）

#### 生物学的対応

- **遺伝子**: ルール1個に対応。プロモーター領域=条件、コード領域=行動
- **転写因子**: 環境条件の検出（センサ入力）
- **オペロン**: 関連ルールのグルーピング
- **発現の独立性**: 1遺伝子の変異が他遺伝子に影響しない

#### プログラム例

```
RULE 0:
  WHEN energy < 300
  DO   recharge_action

RULE 1:
  WHEN phase == 0 AND nearby_ore
  DO   harvest_ore_action

RULE 2:
  WHEN phase == 0 AND count >= 24
  DO   set_phase_to_1
...
```

各ルールはメモリ上の独立した領域に格納され、相互に参照しない。

### 解決すること

- **PCの迷走が原理的に存在しない**: 逐次実行のPCがないため、迷走しようがない。Issue 005の核心問題が消失する
- **1ルールの破損が他ルールに波及しない**: 各ルールは独立しており、破損は局所的
- **進化的に評価しやすい**: 「このルールを追加/削除/変異」のような小さな変更単位が明確

### 解決しないこと

- **ルールエンジン自体（VM）の脆弱性**: ルールエンジンはVMの一部として実装され、これ自体は破損しない（VMはキャラクタープログラムではないため）
- **条件部・行動部のフィールド破損**: ルールの内容自体は破損しうる。ただし1ルール単位の破損で済む
- **複雑な手続き的処理の困難**: 「Aを行い、結果を見てBを行い…」のような順序処理は表現しにくい

### 実現可能性

中〜高。VMの大幅な仕様変更が必要だが、ルールエンジンは比較的シンプルに実装できる。

#### 必要な変更

- VM実行モデルの根本変更（PC方式の廃止または併用）
- ルール表現フォーマットの設計（条件部・行動部のエンコーディング）
- 既存プログラムの全書き換え（または併存可能な設計）
- Mini-Cコンパイラの再設計（または専用DSL導入）

#### 課題

- 「複雑なロジック」の表現力をどう確保するか。ルールだけでは状態機械的処理が冗長になる
- ルールの評価コスト: 全ルールを毎tick評価するのは命令数を消費する
- 既存プログラム資産の廃棄

### この案の本質

**Issue 005の核心問題（PC迷走）を原理的に消滅させる**点で、極めて強力な解決策である。一方、表現力とのトレードオフが大きい。

## 改善案d: 反射・本能の組み込み（hardware-level reflex）

### アイデア

VMやI/Oハンドラのレベルで、プログラムを介さない**生存反射行動**を提供する。

例:
- エネルギーが閾値を下回り、かつ近傍にエネルギーノードがあり、過去N tickにrechargeコマンドが発行されていない → 自動的にrechargeを試みる
- 耐久度が閾値を下回り、過去N tickにrepairコマンドが発行されていない → 自動的にrepairを試みる
- HALTせずN tick経過 → 強制HALT（命令上限の柔軟版）

これらの反射は、Processorのプログラムが完全に破損していても動作する。

#### 生物学的対応

- **脊髄反射**: 大脳を経由しない筋肉制御
- **延髄の自律機能**: 呼吸・心拍などの不随意制御
- **走性**: 単細胞生物の光・化学物質への反応

### 解決すること

- **完全破損したプログラムでも最低限の生存が可能**: 充電・修理を反射で行い、致命的状態を回避
- **進化の空間が広がる**: 「主要な制御は反射に任せ、プログラムは付加的な戦略を持つ」という設計が可能になる
- **緩やかな性能劣化**: プログラムが少し壊れても、反射が補完する

### 解決しないこと

- **反射の対象外の行動**: 収穫・組み立て・複製など、複雑な意思決定が必要な行動は依然プログラムに依存
- **反射が誤作動した場合**: 反射自体は固定なので破損しないが、不適切な状況でも発動する可能性
- **進化との緊張関係**: 反射が常に「正解」を提供すると、進化的探索の必要性が下がる可能性がある

### 実現可能性

**高**。VMやI/Oハンドラに条件付き自動コマンド発行のロジックを追加するだけで実装可能。既存プログラムへの影響は小さい。

#### 課題

- 反射の対象範囲をどこまで広げるか。広げすぎると進化の余地が減る
- 反射の発動条件のチューニング（パラメータ依存）
- 反射が消費するリソース（エネルギー）の扱い

### この案の本質

**Issue 005の核心問題（PC迷走）を直接解決するわけではない**が、迷走したプログラムを持つ個体でも生存し続けられるため、進化的時間スケールでの種の存続を可能にする。

「個体ロバスト性」ではなく「種ロバスト性」を提供する案。

## 改善案e: 有性生殖・遺伝的組換え

### アイデア

複製時に**2親のメモリを混合**して子を作る。

- 2個体が物理的に近接（または明示的な「交配」アクション）したとき、両者のメモリ領域を交差させて子のメモリを作る
- 領域単位（例: 連続する数十ワードの塊）で交互に親Aと親Bから選ぶ
- 1親の破損領域は、もう1親の対応領域が無事であれば子では補われる

#### 生物学的対応

- **減数分裂**: 染色体の組換え
- **配偶子融合**: 2親の遺伝情報の統合
- **ヘテロ接合性**: 劣性致死変異の遮蔽

### 解決すること

- **致死的破損の遮蔽**: 1親に致命的な破損があっても、もう1親が無事なら子は健全
- **進化的探索の加速**: 異なる進化系統の組み合わせ
- **集団内の遺伝的多様性の維持**: 単一系統での近親交配的劣化を防ぐ

### 解決しないこと

- **両親が同じ場所を破損していた場合**: 子も同じ場所が破損する
- **個体自身のロバスト性**: 親個体のPC迷走問題は依然として残る
- **2親の出会いのコスト**: 時間と物理的近接が必要、生殖率が下がる可能性

### 実現可能性

中。新しいゲームメカニクスの追加が必要。

#### 必要な変更

- 「交配」アクション、または「近接時に自動交配」の判定ロジック
- write_memory の2親バージョン
- 子個体の生成プロトコル変更
- 既存プログラム（無性生殖前提）の書き換え

#### 課題

- 親の選択基準（誰と誰が交配するか）
- 物理的近接の判定とコスト
- 既存の単性生殖との共存可否

### この案の本質

**個体ロバスト性ではなく集団ロバスト性**を提供する。生物の有性生殖と同じく、変異の致死率を下げ、多様性を維持する効果がある。

ゲームプレイの観点でも興味深い変化（種内の社会性、配偶者選択の進化）を生む。

## 改善案f: アポトーシス（自発的死）

### アイデア

キャラクターが自身の状態を監視し、「機能不全」と判断したら自発的に死を選択する。死亡時にコンポーネントが残骸として残り、他個体に再利用される。

監視の方法:
- 過去N tickの命令上限到達回数
- 過去N tickのI/Oコマンド発行有無
- グローバル変数の整合性チェック
- エネルギー収支がN tick連続で負

#### 生物学的対応

- **アポトーシス**: 異常細胞の計画的自殺
- **オートファジー**: 細胞内の異常タンパク質の分解
- **免疫系による異常細胞の除去**

### 解決すること

- **致命的破損個体がリソースを浪費し続けない**: 早期に死ぬことで、健全な個体の複製のためにリソースを譲る
- **集団の平均健全性が上がる**: 破損個体が早く除去されるため、種全体としての効率が上がる
- **進化の選択圧の強化**: 「壊れたら早く死ぬ」というのは選択圧そのもの

### 解決しないこと

- **個体の生存性向上には逆効果**: 個体は早く死ぬ
- **判定ロジック自体の破損**: アポトーシス判定が誤動作した場合、健全な個体が死ぬ可能性。VM側に実装すれば回避可能

### 実現可能性

**高**。VM/シミュレーション側で「アクション発行のない期間」「命令上限到達回数」を追跡し、閾値を超えたら強制死亡させる機構を追加するだけ。

#### 課題

- 閾値の設定（厳しすぎると正常個体まで死ぬ、緩すぎると効果がない）
- アポトーシス判定をプログラム制御にするか、システム強制にするか
- 「アポトーシスを回避する変異」が進化する可能性（システム強制ならば防げる）

### この案の本質

**個体ロバスト性ではなく集団・種ロバスト性**を提供する。改善案e（有性生殖）と相補的に働く。

## 改善案g: 形態学的計算 / ハードウェアによる行動

### アイデア

プログラムによる制御の代わりに、**コンポーネントの物理的配置・接続自体**から行動が生成される設計を導入する。

例:
- Sensorコンポーネントが特定の入力を検出すると、隣接するActuatorに直接信号を送る（プログラムを介さない）
- Harvesterは近接する資源を自動的に収穫する（プログラムからの命令なしに）
- コンポーネントの「向き」「接続」が行動を決定する

#### 生物学的対応

- **クモの脚**: 脳の制御なしに歩行に最適化された構造
- **ナマコの神経網**: 中央神経系を持たず分散制御
- **植物の屈光性**: ホルモン濃度勾配だけで光に向かう

### 解決すること

- **プログラム破損の影響範囲が縮小**: プログラムがなくても基本的行動は可能
- **改善案bと整合**: 分散コンポーネント設計と相性が良い
- **新しい進化軸の獲得**: 形態と行動が直結することで、形態進化が即座に行動進化を生む

### 解決しないこと

- **複雑な意思決定**: 戦略的判断には依然プログラムが必要
- **形態自体の進化**: 形態進化のメカニズムが別途必要

### 実現可能性

中〜大。コンポーネント間の物理的相互作用ロジックが必要。改善案bと統合的に設計する必要がある。

### この案の本質

改善案bの一形態とも言える。プログラムの責務をさらに減らし、計算を物理に外部化する。

## 改善案h: 環境への外部化（stigmergy）

### アイデア

個体の記憶ではなく、**環境にマーカーを残す**ことで集団行動を組織する。

- 「ここで収穫した」マーカーを地面に残す
- 他個体はマーカーを読んで行動を決定
- 個体プログラムは「マーカーを残す」「マーカーを読む」という単純なルールだけで済む

#### 生物学的対応

- **アリのフェロモン経路**: 個体は単純な規則だけ、集団として複雑な経路最適化
- **シロアリの巣作り**: 個体の単純な反応の集積として複雑な構造
- **粘菌の経路探索**: 中央制御なしの最適経路発見

### 解決すること

- **個体プログラムを極端に小さくできる**: ロジックが単純な分、破損リスクが下がる
- **集団知能の獲得**: 個体ロバスト性が低くても集団として機能
- **環境が永続記憶として機能**: 個体死亡時の知識喪失を防ぐ

### 解決しないこと

- **個体の生存判断**: 個体レベルの即時行動は依然必要
- **環境マーカー自体の永続性**: マーカーがどう劣化・更新されるか別途設計が必要

### 実現可能性

中。地面グリッドにマーカー情報を追加する仕組みが必要。v3で検討した地面の状態管理と相性が良い可能性がある。

#### 課題

- マーカーの種類と表現方法
- マーカーの劣化・上書きルール
- I/Oコマンドへのマーカー読み書き機能の追加

### この案の本質

「プログラムは環境とコンポーネントの間の単純な変換器」と再定義する。記憶と知能の大部分を環境に外部化する設計。

## 提案の統合的視点

各改善案がカバーする問題領域と効果範囲:

| 案 | PC迷走を直接解決 | 個体生存性 | 集団・種ロバスト性 | 進化との相性 |
|----|--------------|-----------|---------------|------------|
| a (符号化冗長化) | 部分的 | 中 | 低 | 高（中立変異） |
| b (分散制御) | 部分的（局所化） | 中 | 中 | 中 |
| c (イベント駆動) | **完全** | **高** | 高 | 中 |
| d (反射) | 否（迂回） | **高** | 中 | 中 |
| e (有性生殖) | 否 | 低 | **高** | **高** |
| f (アポトーシス) | 否 | 否（むしろ短命化） | **高** | **高** |
| g (形態学的計算) | 部分的（プログラム責務縮小） | 中 | 高 | 高 |
| h (環境外部化) | 部分的（プログラム責務縮小） | 中 | **高** | 中 |

## 推奨される組み合わせ

生物が複数の機構を組み合わせて変異ロバスト性を実現しているように、これらの提案も**単独でなく組み合わせる**ことで真の効果を発揮する。

### 組み合わせ案1: 「個体は壊れやすい、種は強い」モデル

**構成**: e (有性生殖) + f (アポトーシス) + d (反射)

- 個体ロバスト性は強化しない
- 反射により最低限の生存を保証
- 壊れた個体は早期にアポトーシス
- 有性生殖により集団内の致死変異を遮蔽
- 種としては高い変異耐性

これは生物学に最も忠実なモデル。個体は短命でも、種は長期的に進化を続ける。

### 組み合わせ案2: 「個体ロバスト性を根本から獲得」モデル

**構成**: c (イベント駆動) + a (符号化冗長化)

- PC迷走問題を原理的に消滅させる
- 中立的変異を獲得
- 個体レベルで強いロバスト性
- 既存ゲーム仕様からの逸脱は大きい

ゲームシステムを根本から設計し直す覚悟が必要。

### 組み合わせ案3: 「身体性と環境を活用」モデル

**構成**: b (分散制御) + g (形態学的計算) + h (環境外部化)

- プログラムの責務を最小化し、計算を物理と環境に外部化
- 進化の単位がコンポーネントレベルに小さくなる
- 本プロジェクトの最終目標（自律的活動の創発）に最も近い方向性

長期的なビジョンとしては最も野心的。

## Issue 005の核心問題への対応

PC迷走問題に対する各案の対応:

- **原理的解決**: 案c（PCを廃止）
- **影響の局所化**: 案b（小さなProcessor単位）、案d（プログラムを介さない反射）
- **集団レベルでの吸収**: 案e、f
- **回避（責務縮小）**: 案g、h
- **個体内の中立化**: 案a

「個体内でPC迷走から復帰する」という当初の問題設定そのものが、生物学的視点では狭すぎる。生物は個体の脳の損傷から完全には復帰しないが、種としては進化を続ける。**個体ロバスト性に固執せず、集団・種・環境を含めたシステム全体としてロバスト性を実現する**のが生物学的なアプローチである。

## 推奨される次のステップ

短期的に試験可能な順:

1. **改善案d (反射) の試験導入**: 実装コストが低く、既存システムへの影響も小さい。エネルギー反射のみから始める
